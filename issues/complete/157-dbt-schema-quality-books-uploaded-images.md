# Issue #157: dbt schema quality — visibility_tier and book_ids constraints

## Summary
Two missing data-quality tests in `dbt/models/staging/schema.yml`: `stg_books.visibility_tier` has no `accepted_values` constraint, and `stg_uploaded_images.book_ids` has no `not_null` assertion for the resolved state.

## User Stories
US-1.1.4, US-1.1.7

## Goal
`dbt test --select staging` enforces that `visibility_tier` is always one of the valid tiers, and that resolved uploaded_images always have a `book_ids` value.

## Scope Check
- Schema.yml edits only — no production code, no migrations.

## Wiring
- [x] Implementation only.

## Technical Requirements

File: `dbt/models/staging/schema.yml`

### Change 1 — `stg_books.visibility_tier` accepted_values
Find the `stg_books` model's `visibility_tier` column entry and add:
```yaml
tests:
  - accepted_values:
      values: ['public', 'age_gated', 'private']
```
Check `apps/core/priv/repo/migrations/` or the `books` schema for the full list of valid tiers before writing the constraint.

### Change 2 — `stg_uploaded_images.book_ids` not_null when resolved
The `book_ids` column is an array. Add a conditional `not_null` test:
```yaml
tests:
  - not_null:
      where: "status = 'resolved'"
```
This asserts that every resolved image has a non-null `book_ids` value (empty-array vs null is handled at the application layer).

## Reviewer Context
- All 30 staging models are proto-generated by `mix proto.sync` — do NOT edit the `.sql` files. `schema.yml` is the correct place for dbt data tests.
- The `stg_uploaded_images` model already has `not_null` on `status`, `accepted_values` on status, and a `relationships` test on `book_id` (added in the test/111 branch). Build on that.
- Check current `visibility_tier` values in `apps/core/lib/stacks/books/book.ex` or migrations.
