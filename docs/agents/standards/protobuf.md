# The Stacks — Protobuf Standards

## Philosophy

`.proto` files are the single source of truth for all structured data contracts in The Stacks. They define the shapes of partner API payloads, internal event bus messages, and service-to-service communication. JSON on the wire, Protobuf for schema enforcement.

---

## File Organisation

```
proto/
├── buf.yaml                    # Module config, lint rules
├── buf.gen.yaml                # Retained for `buf lint`/`buf breaking`; plugin entries are commented out — see Code Generation below
├── persisted.exs               # Manifest mapping proto messages → persisted DB tables (ADR-009)
├── gen/                        # Buf JSON descriptor output (consumed by custom generators)
└── stacks/
    ├── api/v1/                 # Public API request/response envelopes
    ├── common/v1/              # Shared types (book, listing, location, user, …)
    ├── infra/v1/               # Infrastructure schemas (e.g. book_cache)
    ├── internal/v1/            # Internal system schemas (event_bus, vision, partner, scraper, audit)
    ├── monitoring/v1/          # Monitoring schemas (source health checks)
    └── partner/                # Reserved for future partner-facing schemas
```

### Naming Conventions
- Package: `stacks.<domain>.v<N>` (e.g., `stacks.api.v1`, `stacks.internal.v1`, `stacks.common.v1`)
- Directory mirrors the package: `proto/stacks/<domain>/v<N>/`
- Message names: PascalCase (`InventoryItem`, `EventEnvelope`)
- Field names: snake_case (`price_cents`, `event_type`)
- Enum names: UPPER_SNAKE_CASE (`BOOK_CONDITION_NEW`)
- Enum zero value: always `*_UNSPECIFIED = 0`

---

## Schema Evolution Rules

These rules are non-negotiable. `buf breaking` enforces them in CI.

| Change | Allowed? | How |
|--------|----------|-----|
| Add a new field | Yes | Use next available field number |
| Add a new enum value | Yes | Never at position 0 (that's UNSPECIFIED) |
| Remove a field | No | Mark as `reserved` instead |
| Change field type | No | Add a new field with the new type |
| Rename a field | JSON only | Use `json_name` option if needed |
| Change field number | Never | |
| Reuse a field number | Never | |
| Remove an enum value | No | Mark as `reserved` |

### Reserving Fields
```protobuf
message InventoryItem {
  reserved 6;              // was: old_field (removed in v2)
  reserved "old_field";    // prevent name reuse too

  string isbn = 1;
  int32 price_cents = 2;
  // ... field 6 is permanently reserved
}
```

## Code Generation

`buf generate` is **not** the active codegen path. The project uses a custom generator (`scripts/gen_python_proto.py`) that reads the buf JSON descriptor and emits idiomatic output for each language. `buf.gen.yaml` is retained so `buf lint` and `buf breaking` continue to work; its plugin entries are intentionally commented out to prevent accidental `buf generate` runs from producing files in the wrong locations.

Codegen is orchestrated by the umbrella Mix task `mix proto.sync`, which fans out to per-language helper scripts.

### Generated Code Locations
| Language       | Output                                | Generator                                 | Git Status                |
|----------------|---------------------------------------|-------------------------------------------|---------------------------|
| Elixir (Ecto)  | `apps/core/lib/stacks/gen/`           | `mix proto.sync` (via `gen-ecto-proto.sh` / `gen-elixir-proto.sh`) | **Checked in** — regenerated by `mix proto.sync` |
| dbt staging    | `dbt/models/staging/`                 | `mix proto.sync`                          | **Checked in** — regenerated by `mix proto.sync` |
| Python         | `apps/vision/app/proto/gen/`          | `scripts/gen-python-proto.sh`             | **Checked in** — regenerated at build time |
| Rust           | `apps/scraper/src/proto/`             | `scripts/gen-rust-proto.sh`               | **Checked in** — regenerated at build time |
| Elm            | `proto/gen/elm/`                      | `scripts/gen-elm-proto.sh`                | **Gitignored** — regenerated at build time |

`mix proto.sync` also produces the `ProtoJSON.Gen` module, schema.yml entries, and migrations driven by `proto/persisted.exs` (the manifest mapping proto messages → DB tables; see ADR-009).

### Elm Exception
Elm cannot run code generation at runtime. The Elm decoders/encoders are generated by `scripts/gen-elm-proto.sh` and gitignored. The build pipeline (`just setup`, `just dev`, `scripts/deploy-stack.sh`) regenerates them automatically. CI runs `scripts/gen-elm-proto.sh --check` to verify the generator would produce the same output.

### Generation Commands
```bash
mix proto.sync               # Regenerate Ecto schemas, dbt staging, ProtoJSON.Gen, migrations
mix proto.sync --check       # Drift check (used in CI — fails the build if regen would change files)
scripts/gen-python-proto.sh  # Vision sidecar (Pydantic v2)
scripts/gen-rust-proto.sh    # Scraper (serde)
scripts/gen-elm-proto.sh     # Frontend decoders/encoders
```

## buf Configuration

### buf.yaml
```yaml
version: v2
lint:
  use:
    - STANDARD
    - COMMENTS
  enum_zero_value_suffix: _UNSPECIFIED
  disallow_comment_ignores: true
breaking:
  use:
    - FILE
```

`STANDARD` + `COMMENTS` enforces docstrings on every package, service, message, enum, and field. `disallow_comment_ignores: true` prevents per-file `// buf:lint:ignore` suppressions — exceptions must be declared centrally in `buf.yaml` (e.g. the `breaking.ignore_only` block).

### buf.gen.yaml
Retained for `buf lint` / `buf breaking` only. All plugin entries are intentionally commented out — see Code Generation above.

## CI Integration

Every PR that touches `proto/**` (or the generated outputs) triggers:

```yaml
- name: Lint proto files
  run: scripts/lint-proto.sh         # buf lint

- name: Check for breaking changes
  run: buf breaking proto/ --against '.git#branch=main'

- name: Check for codegen drift
  run: mix proto.sync --check        # fails if regen would change files
```

All three must pass. No exceptions.

## Event Upcasting

When an event schema evolves, old events in `event_log` need to be transformed to the current shape on read. This is handled by `Stacks.Events.Upcaster`.

### Pattern
```elixir
defmodule Stacks.Events.Upcaster do
  # v1 -> v2: added currency field
  def upcast(%{"event_type" => "inventory.updated", "schema_version" => 1} = event) do
    event
    |> update_in(["payload"], &Map.put_new(&1, "currency", "ZAR"))
    |> Map.put("schema_version", 2)
    |> upcast()  # chain to next version
  end

  # Current version: passthrough
  def upcast(event), do: event
end
```

### Rules
- Each version bump is one function clause
- Upcasters chain: v1 -> v2 -> v3 (never skip versions)
- Every upcaster must have a unit test with a fixture of the old event shape
- The passthrough clause (`def upcast(event), do: event`) handles current-version events

### When to Add an Upcaster
- When you add a required field to an event payload
- When you rename a field in an event payload
- When you change the structure of an event payload
- You do NOT need an upcaster for purely additive optional fields (consumers can handle missing keys)

## Relationship to Database Schema

Proto schemas and Ecto schemas serve different purposes:
- **Proto:** Defines the wire format (what partners send, what events contain)
- **Ecto:** Defines the storage format (what PostgreSQL stores)

For tables listed in `proto/persisted.exs`, the Ecto schema is **generated** from the proto message by `mix proto.sync` and written to `apps/core/lib/stacks/gen/` — they are not hand-edited and not required to drift from the proto. Tables not in the manifest are hand-rolled Ecto schemas; the Elixir application layer translates between them and the wire format.
