# US-15.1.1 — View the Home Page

## 1. User Story

> **As a** visitor or a returning reader, **I want** the root URL to meet me where I am — a welcoming introduction if I'm not signed in, and a way straight into my collection if I am — **so that** `/` is never a dead end.

The home page is **two faces of one route**. Signed out, it is a welcoming landing page that says what The Stacks is and where to go next. Signed in, it stops being a marketing hero and becomes a threshold into the reader's own collection.

**What the authenticated reader wants to accomplish:** Land on `/` and immediately have a path into their books — a glimpse of a shelf, a nudge to pick up where they left off, and an ever-present way to add the next book — rather than being shown a page that pitches a product they already use.

**Acceptance criteria:**
- The home page renders at the root URL (`/`) for all users and adapts to auth state (it does not force a redirect — the authed reader lands on a *useful* `/`, not a bounce to `/antilibrary`).
- **Unauthenticated variant:** displays the platform title ("The Stacks") and subtitle ("Your personal collection, beautifully organised."), with "About The Stacks" → `/about` and "Browse the Marketplace" → `/marketplace`. This keeps the welcoming landing role.
- **Authenticated variant:** routes the reader into their collection. The intent is a lightweight home-into-collection surface, not a static hero. Proposed widget set (exact composition confirmed during 8c design, #318): a **shelf preview** (a glimpse of the reader's shelves), a **continue-reading** entry point (jump back into the Reading Pile), and a **persistent Add-Book CTA** as a primary action.
- The visual aesthetic follows the dark-academic-meets-cottage-core style established by CLAUDE.md.

> (`/about`) and "Browse the Marketplace" (`/marketplace`), replacing the earlier "View Antilibrary"

**What they see on the page:**

*Unauthenticated:* a calm, centred landing — "The Stacks" in the serif title, the subtitle beneath it, and two clear actions ("About The Stacks", "Browse the Marketplace"). It reads as an invitation, giving a first-time visitor a sense of the place and one obvious next step.

*Authenticated:* the reader lands not on a pitch but on the doorway to their own collection. A **shelf preview** shows a glimpse of their books — a few spines from a shelf, rendered in the same warm shelf-room aesthetic as the bookshelf pages — so the page feels like *theirs* the moment it loads. A **continue-reading** cue offers a direct way back into the Reading Pile (the book they're mid-way through, or a prompt to start one). A **persistent Add-Book call to action** sits as a primary affordance, so adding the next book is always one click from home. The overall feeling is of stepping back into a room you've been furnishing, not being greeted by a stranger at the door. (Exact widget composition is confirmed in 8c design, #318; the intent above is the bar.)

## 2. UI Interaction Flow

### Happy Path (Unauthenticated)
1. User navigates to the root URL (`/`).
2. Route resolves to `Route.Home`.
3. `initPage` checks auth state; unauthenticated → renders the landing variant of `PageHome`.
4. `viewHome` renders a centred layout with title, subtitle, and the About / Marketplace action buttons.

### Authenticated User on Home
1. Authenticated user navigates to `/`.
2. Route resolves to `Route.Home`.
3. `viewHome` (or its authed branch) renders the **home-into-collection** surface rather than the marketing landing: a shelf preview, a continue-reading entry point, and a persistent Add-Book CTA. `/` is not redirected away — it resolves to a useful, collection-oriented home.
4. The reader clicks a shelf-preview spine (→ book detail overlay / that shelf), the continue-reading cue (→ Reading Pile), or Add Book (→ the upload flow, US-1.1.1).

### Elm State Machine
- **Page module**: `Page.Home` (or an authed branch of the home view in Main.elm), replacing the purely-inline static `viewHome`. The unauthenticated face stays model-light; the authenticated face needs enough model to hold the shelf-preview data.
- **Model fields (authed)**: a small `RemoteData` field for the shelf-preview / continue-reading data (e.g. `preview : RemoteData Http.Error HomePreview`); unauthenticated renders with no model.
- **API calls**: unauthenticated → none; authenticated → a lightweight read for the shelf preview / continue-reading state (exact endpoint set finalised in 8c design).

---

## 3. API Calls

The **unauthenticated** home is entirely static client-side content — no API calls. The **authenticated** home makes a lightweight read to populate the shelf preview / continue-reading widgets (reusing existing bookshelf/placement reads such as `GET /api/bookshelves/:name` — see US-1.2.1 / US-1.2.4 — rather than a bespoke endpoint). The exact call set is finalised during 8c design (#318); the Add-Book CTA itself navigates into the upload flow (US-1.1.1) and issues no call from the home page.

---

## 4. Auth & Middleware Guards

- **Server-side**: The root URL `/` is handled by the catch-all route `get "/*path", PageController, :index` which serves the Elm SPA HTML.
- **Client-side**: `/` renders for everyone — it never redirects. The *content* branches on auth state: unauthenticated → the static landing; authenticated → the collection-routing home, whose preview read rides the standard `:authenticated` API pipeline.

## 12. Elm Frontend State Machine (Detail)

### Route
- **Route variant**: `Route.Home`
- **URL**: `/`
- **Public or authenticated**: Public (`requiresAuth` returns `False`)

### Init
- **`initPage` branch**: `Home` → unauthenticated renders the static landing (`Cmd.none`); authenticated fires the lightweight shelf-preview / continue-reading read.
- **API calls on init**: unauthenticated → none; authenticated → the preview read (8c-finalised).
- **Initial model state**: unauthenticated → no model; authenticated → `{ preview = Loading }` (or equivalent).

### Update cycle
- **Unauthenticated**: no messages handled.
- **Authenticated**: `PreviewLoaded (Ok data)` → `preview = Success data`; `PreviewLoaded (Err e)` → `preview = Failure e` (home still renders with the Add-Book CTA and continue-reading affordance degraded gracefully); clicks on preview spines / continue-reading / Add Book emit `NavigateTo` out-messages.

### View
- **Unauthenticated `viewHome`** renders:
  - `div.page.page--home`
  - `h1.home__title` — "The Stacks"
  - `p.home__subtitle` — "Your personal collection, beautifully organised."
  - `div.home__actions` with two links (shipped markup, #235):
    - `a.btn.btn--primary.home__link--about` linking to `/about` — "About The Stacks"
    - `a.btn.btn--secondary.home__link--marketplace` linking to `/marketplace` — "Browse the Marketplace"
- **Authenticated home** renders the collection-routing surface: a shelf-preview region (spines in the shelf-room aesthetic), a continue-reading entry point into the Reading Pile, and a persistent primary Add-Book CTA. Exact markup/classes are settled in 8c design (#318); the widget intent above is the spec.
- **Browser tab title**: "The Stacks" (via `pageTitle Home`)
- **ARIA attributes**: shelf-preview spines and CTAs carry meaningful labels (per US-19.1.1).
- **CSS classes**: `page--home`, `home__title`, `home__subtitle`, `home__actions` (unauth); the authed home reuses shelf-room and CTA classes finalised in 8c.

## 13. Operational Metrics

- **Home page load rate**: Count of `Route.Home` renders per day, split by authenticated vs unauthenticated visitors.
- **Bounce rate**: Percentage of unauthenticated home page visits that do not result in navigation to another page.
- **Unauth CTA click-through**: Ratio of "About The Stacks" and "Browse the Marketplace" clicks to total unauthenticated home renders.
- **Authed home routing rate**: Percentage of authenticated home visits that route onward into the collection — shelf-preview spine click, continue-reading, or Add Book. A high rate confirms the home now does its job (the inverse of the old drift).
- **Add-Book CTA click-through (authed)**: Share of authenticated home visits that click the persistent Add-Book CTA.

---

## 14. Performance & Usability Metrics

- **Home page render time**: Unauthenticated → time from route resolution to first paint, <50ms (static). Authenticated → time to the collection-routing home being interactive, including the shelf-preview read (target comparable to a light bookshelf load, p95 < ~800ms).
- **Authed home onward-navigation**: How many authenticated visitors land on `/` and then route into their collection (vs leave). This is the success signal that replaced the old drift — the home is meant to be a doorway, not a wall.
- **Time-on-page**: Average dwell time, split by variant. For the authed home, dwell that ends in an onward click into the collection is the healthy pattern.
- **Navigation path from home**: Most common next route after the home page — for authed readers, expected to be a shelf, the Reading Pile (continue-reading), or the upload flow (Add Book).

## 15. Cost Tracking

- **Unauthenticated home**: served by the SPA catch-all route (`PageController.index`). No API calls, no database reads, no external services — a static HTML serve from Fly.io. Effectively $0.00.
- **Authenticated home**: adds one lightweight shelf-preview / continue-reading read per load (reusing existing bookshelf reads, US-1.2.1/US-1.2.4). Negligible Neon cost, comparable to a light bookshelf load; no external services.
- **Total cost**: near-zero — the only cost is the authed preview read, amortised against the reads it reuses.
