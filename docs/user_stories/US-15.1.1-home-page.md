# US-15.1.1 — View the Home Page

## 1. User Story

> **As a** user, **I want to** see a welcoming landing page when I visit The Stacks **so that** I understand what the platform is and can navigate to my collection or add a book.

**Acceptance criteria:**
- The home page renders at the root URL for unauthenticated users
- Authenticated users visiting `/` are redirected to `/antilibrary`
- The page displays the platform title and subtitle
- "Sign In" navigates to the authentication page
- The page is only shown to unauthenticated users

---

## 2. UI Interaction Flow

### Happy Path (Unauthenticated)
1. User navigates to the root URL (`/`).
2. Route resolves to `Route.Home`.
3. `initPage` checks `requiresAuth Home` -> `False`, renders `PageHome`.
4. `viewHome` renders a centred layout with title, subtitle, and action buttons.

### Authenticated Redirect
1. Authenticated user navigates to `/`.
2. Route resolves to `Route.Home`.
3. `viewHome` renders — but the actual content shows "View Antilibrary" and "Add a Book" buttons (no redirect is forced in the current implementation). The spec says authenticated users should be redirected to `/antilibrary`, but the current code renders the home page with links to the antilibrary instead.

### Elm State Machine
- **Page module**: N/A (inline `viewHome` function in Main.elm)
- **Model fields**: None — `PageHome` is a static page variant with no model.
- **No API calls**, no state machine.

## 4. Auth & Middleware Guards

- **Server-side**: The root URL `/` is handled by the catch-all route `get "/*path", PageController, :index` which serves the Elm SPA HTML. No API call is made.
- **Client-side**: `requiresAuth Home` returns `False`, so the page renders regardless of auth state.

## 12. Elm Frontend State Machine (Detail)

### Route
- **Route variant**: `Route.Home`
- **URL**: `/`
- **Public or authenticated**: Public (`requiresAuth` returns `False`)

### Init
- **`initPage` branch**: `Home -> ( PageHome, Cmd.none )`
- **API calls on init**: None
- **Initial model state**: `PageHome` has no model.

### Update cycle
N/A — No messages handled for the home page.

### View
- **`viewHome`** renders:
  - `div.page.page--home`
  - `h1.home__title` — "The Stacks"
  - `p.home__subtitle` — "Your personal collection, beautifully organised."
  - `div.home__actions` with two links:
    - `a.btn.btn--primary` linking to `/antilibrary` — "View Antilibrary"
    - `a.btn.btn--secondary` linking to `/upload` — "Add a Book"
- **Browser tab title**: "The Stacks" (via `pageTitle Home`)
- **ARIA attributes**: None specific to the home page.
- **CSS classes**: `page--home`, `home__title`, `home__subtitle`, `home__actions`

## 13. Operational Metrics

- **Home page load rate**: Count of `Route.Home` renders per day, split by authenticated vs unauthenticated visitors.
- **Bounce rate**: Percentage of unauthenticated home page visits that do not result in navigation to another page.
- **CTA click-through rate**: Ratio of "View Antilibrary" and "Add a Book" button clicks to total home page renders (authenticated users only).
- **Sign In navigation rate**: Percentage of unauthenticated home page visits that lead to `/login` navigation.

---

## 14. Performance & Usability Metrics

- **Home page render time**: Time from route resolution to first paint. Should be <50ms (static page, no API calls, no model).
- **Authenticated redirect behaviour**: Currently authenticated users see the home page with links instead of being redirected to `/antilibrary`. Track how many authenticated users land on `/` and whether they immediately navigate away.
- **Time-on-page**: Average dwell time on the home page. Very short times for authenticated users confirm the need for auto-redirect.
- **Navigation path from home**: Most common next route after viewing the home page (expected: `/login` for unauthenticated, `/antilibrary` for authenticated).
