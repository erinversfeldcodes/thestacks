# US-14.1.2 — First-Time Onboarding Flow

## 1. User Story

> **As a** new user who has just registered, **I want** a brief guided introduction to adding my first book **so that** I understand how The Stacks works without feeling overwhelmed or lost.

After successful registration and email confirmation, the system launches a lightweight onboarding overlay on the user's first login. The overlay is a 3-step flow: Welcome, Upload prompt, and Complete.

> **Backend cross-ref**: Issue #149 (complete) replaced the boolean `users.onboarding_completed` with a JSONB `users.onboarding_steps` map (`profile`, `age_verification`, `privacy`) and added `GET /api/onboarding/status` / `PUT /api/onboarding/step/:step`. `onboarding_completed` is now a `GENERATED ALWAYS AS` column derived from those steps. The frontend overlay described below remains client-side, but server-side step granularity is now available via `Stacks.Accounts.onboarding_status/1` and `complete_onboarding_step/2` — see Issue #149 for the canonical step list.

**Acceptance criteria:**
- Onboarding launches after first registration only (not on subsequent logins)
- The flow is fully dismissable at any step via the "Skip" link
- Skipping redirects to `/antilibrary`
- Completing the flow places the first book on the chosen shelf and redirects there
- The onboarding state is stored via localStorage port so it never re-triggers

## 2. UI Interaction Flow

### Happy Path
1. User logs in for the first time (no placements exist, `onboardingCompleted` is `false` in localStorage).
2. The onboarding overlay renders on top of the current page.
3. **Step 1 — Welcome**: "Welcome to The Stacks" heading, "Your personal collection, beautifully organised." tagline. Two buttons: "Get started" (advances) and "Skip" (dismisses).
4. **Step 2 — Upload prompt**: "Upload your first book" heading, instructions to take a photo or enter an ISBN. "Continue" and "Skip" buttons.
5. **Step 3 — Complete**: "Welcome to your library" heading, "Your shelves are ready. Start exploring and organising your books." A single "Start exploring" button.
6. Progress dots (3 dots at bottom) indicate current step.

### Sad Paths
- **Skip at any step**: Overlay closes, `saveOnboardingCompleted` port fires, user sees the underlying page. Onboarding never re-triggers.

### Elm State Machine
- **Page module**: `Components.OnboardingOverlay`
- **Model fields involved**: `step` (`Welcome` | `UploadPrompt` | `Complete`), `visible` (Bool)
- **Msg flow**: `NextStep` -> advance `step` from `Welcome` -> `UploadPrompt` -> `Complete`; `SkipOnboarding` -> hide overlay, emit `SkipCompleted`; `FinishOnboarding` -> hide overlay, emit `FinishCompleted`.
- **OutMsg pattern**: `SkipCompleted` and `FinishCompleted` propagate to Main.elm, which sets `onboardingCompleted = True` and calls `saveOnboardingCompleted ()` port.

## 12. Elm Frontend State Machine (Detail)

### Route
- **Route variant**: N/A — The onboarding overlay is not route-based. It renders on top of any page when conditions are met.
- **Display condition**: `model.auth == Just _` AND `not model.onboardingCompleted` AND `not model.hasAnyPlacements`

### Init
- **Component init**: `OnboardingOverlay.init` returns `{ step = Welcome, visible = True }`
- **Main.elm init**: On app startup, calls `requestOnboardingStatus ()` port to check localStorage. Also calls `Api.getMyPlacements` to check if user has any existing placements.
- **Port interaction**: `requestOnboardingStatus` port asks JS for localStorage value; JS responds via `onOnboardingStatus` port subscription with a Bool.

### Update cycle
- **Msg**: `NextStep`
  - `Welcome` -> `{ model | step = UploadPrompt }`, OutMsg `NoOut`
  - `UploadPrompt` -> `{ model | step = Complete }`, OutMsg `NoOut`
  - `Complete` -> `{ model | visible = False }`, OutMsg `FinishCompleted`
- **Msg**: `SkipOnboarding` -> `{ model | visible = False }`, OutMsg `SkipCompleted`
- **Msg**: `FinishOnboarding` -> `{ model | visible = False }`, OutMsg `FinishCompleted`
- **Main.elm handling**: On `SkipCompleted` or `FinishCompleted`, sets `model.onboardingCompleted = True`, calls `saveOnboardingCompleted ()` port (writes to localStorage).
- **Main.elm**: `OnboardingStatusReceived completed` -> sets `model.onboardingCompleted = completed`

### View
- **Key elements**: Full-screen overlay with backdrop, card with step content, progress dots.
- **ARIA attributes**: `role="dialog"`, `aria-modal="true"`, `aria-label="Welcome to The Stacks"`, `tabindex=-1` on the overlay container.
- **CSS classes**: `onboarding-overlay`, `onboarding-overlay__backdrop`, `onboarding-overlay__card`, `onboarding-overlay__step`, `onboarding-overlay__title`, `onboarding-overlay__tagline`, `onboarding-overlay__actions`, `onboarding-overlay__dots`, `onboarding-overlay__dot`, `onboarding-overlay__dot--active`
- **Button styles**: "Get started" / "Continue" / "Start exploring" use `btn btn--primary`; "Skip" uses `btn btn--ghost`.

## 13. Operational Metrics

- **Onboarding trigger rate**: Percentage of first-time logins where the onboarding overlay renders (should be 100% when `onboardingCompleted == false` and no placements exist).
- **Step progression rate**: Count of users reaching each step (Welcome -> UploadPrompt -> Complete). Tracked client-side only (no API calls).
- **Skip rate per step**: Percentage of users clicking "Skip" at each step (Welcome, UploadPrompt, Complete). Higher skip rates on early steps indicate poor engagement.
- **Completion rate**: Percentage of users who reach the Complete step and click "Start exploring" vs those who skip at any point.
- **localStorage write success**: Port call `saveOnboardingCompleted` success rate. Failures would cause re-triggering on next login.

---

## 14. Performance & Usability Metrics

- **Onboarding completion vs skip rate**: Primary conversion metric. Target: >50% completion rate. Low completion suggests the flow is too long or not compelling.
- **Time-to-completion**: Elapsed time from overlay render to "Start exploring" click. Indicates engagement level.
- **Time-per-step**: Average time spent on each step. Long dwell on UploadPrompt may indicate confusion about the upload process.
- **First book placement rate**: Percentage of users who complete onboarding and place their first book within the same session (ties to US-14.1.2 goal).
- **Overlay render performance**: Time from `initPage` to overlay visible. Should be <100ms (no API calls, purely client-side rendering).
- **Re-trigger rate**: How often the onboarding re-appears after being completed (indicates localStorage port failures).
