# US-10.5.4 — Discover Readers

> The entry points to a profile. A profile page nobody can reach is invisible, so
> this story wires the two ways to arrive: a blog author's name links to their
> profile, and a people-search finds discoverable readers. Both must honour
> profile visibility — "Discoverable" (US-10.1.1) is what makes a reader findable.

## 1. User Story

**As a** reader, **I want to** find other readers — by following a blog author's
name or by searching — **so that** I can discover profiles and libraries worth
browsing.

### Acceptance criteria — the discoverability privacy rule

- **Blog author link**: on `/blog/:id`, the author's display name links to
  `/u/:author_handle`. The post payload carries `author_handle` (from the
  already-preloaded `post.user`).
- **People search** (`GET /api/search/users?q=...`): returns only readers with
  `profile_visibility = "platform"` ("Discoverable"):

| Target | Appears in search results? |
|---|---|
| `profile_visibility = platform` (Discoverable), not blocked | **yes** |
| `profile_visibility = owner` (Ghost) | **never** |
| blocked (either direction) w.r.t. the searcher | **never** |
| any tighter/unlisted future tier | **never** |

- **Exclusion is enforced in the SQL query**, not by redacting the serializer —
  a ghost or blocked user must never appear in a result set at all.
- Results are the redacted `public_profile` shape (handle + display_name +
  location), each linking to `/u/:handle`.
- Following an author link to a ghost/blocked profile still lands on the
  US-10.5.2 gate → "Reader not found" (defence in depth: link discovery never
  bypasses the profile gate).

## 2. UI Interaction Flow

### Happy path
- Blog: click an author's name → their profile.
- Search: type a name in the people search → a list of discoverable readers → click → their profile.

### Sad paths
- No matches → empty state.
- A ghost you know the handle of → still 404 at the profile (US-10.5.2).

## 3. API Calls
- `GET /api/blog/posts/:id` — now includes `author_handle`.
- `GET /api/search/users?q=<term>` → returns `[public_profile]` filtered to discoverable, non-blocked readers by `display_name ILIKE`.

## 4. Auth & Middleware Guards
Search runs under `:optional_auth` (block-exclusion needs the viewer when signed in). Author links are public.

## 5. Database Interactions
`Accounts.search_users(term, viewer)` — a single query: `WHERE profile_visibility = 'platform' AND display_name ILIKE '%term%'` AND the pair is not blocked (subquery/anti-join on `user_blocks` in both directions). **No result may be filtered only in Elixir/serializer.**
