# US-10.5.1 — Claim a Public Handle

> Part of the **Privacy & Visibility** epic (US-10.x). This is the identity half of
> the *reader-facing* surface: a stable, human-readable handle that keys a user's
> public profile at `/u/:handle`. The visibility *enforcement* (US-10.1.1 profile
> visibility, US-10.2.x shelf/placement visibility) is what gates the profile;
> this story is only about the handle that addresses it.

## 1. User Story

**As a** reader, **I want** a unique public handle **so that** others can find my
profile at a memorable URL (`/u/:handle`) instead of a UUID.

### Acceptance criteria
- Every user has a handle — one is auto-generated at registration (`slug(display_name) + _<random>`; `reader_<random>` when the display name is blank) so no account is ever without a reachable profile URL.
- A user can change their handle in Settings → Profile.
- A handle is **3–30 chars, lowercase `[a-z0-9_]`**, case-insensitively **unique**, and not a **reserved word** (any top-level route segment, or impersonation-sensitive words like `admin`/`api`/`support`).
- Handles are normalised to lowercase on save; `AdaLovelace` and `adalovelace` are the same handle and cannot both exist.
- Rejections surface a specific 422 error: taken, reserved, or bad format.
- A handle is **not PII** — it is a user-chosen public identifier and is safe in the warehouse; email/consent/role are never exposed alongside it.

## 2. UI Interaction Flow

### Happy path
Settings → Profile shows the current handle in an editable field → user edits it → Save → "Saved!" and the field reflects the normalised (lowercase) value.

### Sad paths
- Taken → "That handle is already taken."
- Reserved → "That handle is reserved."
- Bad format → "Handle must be 3–30 characters: lowercase letters, numbers, underscores."

### Elm state machine
`SetHandle String` updates the field; `SaveProfile` PUTs; `SaveProfileCompleted (Err 422)` renders the field error from the changeset.

## 3. API Calls

### `PUT /api/settings/profile`
Extends the existing profile update — accepts `handle` alongside `display_name`/`website_url`. 200 returns `{display_name, website_url, email, handle}`; 422 `{errors: {handle: [...]}}` on taken/reserved/format. No new endpoint. `GET /api/auth/me` and login now include `handle` so the client knows its own.

## 4. Auth & Middleware Guards
`:authenticated` pipeline (own account only). A user can only change their own handle.

## 5. Database Interactions
- `op.users.handle` — `text`, `NOT NULL`, backfilled for existing rows.
- Case-insensitive uniqueness: `CREATE UNIQUE INDEX ON op.users (lower(handle))`.
- `Accounts.get_user_by_handle/1` — case-insensitive lookup (`lower(handle) = lower($1)`).
- Validation in `Accounts.validate_handle/1`: force-lowercase, `~r/^[a-z0-9_]{3,30}$/`, `validate_exclusion` against `Stacks.Accounts.ReservedHandles`, `unique_constraint(:handle, name: :users_lower_handle_index)`.
