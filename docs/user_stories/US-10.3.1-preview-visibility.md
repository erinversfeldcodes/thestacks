# US-10.3.1 — Preview Content Visibility

## 1. User Story

> **As a** user, **I want to** preview how my profile and content appear to different audiences **so that** I can verify my visibility settings are correct before assuming they work.

"I set my shelf to close-friends only -- I want to confirm my mum can't see it even though my profile is discoverable."

The user chooses a viewing perspective:
- **Not logged in** -- simulates an unauthenticated visitor.
- **Anyone on the platform** -- simulates a logged-in stranger.
- **Specific user** -- types a name and previews exactly what that person sees.
- **Group member** -- not yet implemented; returns 422.

The platform renders a read-only view with a persistent banner: "Previewing as [perspective] -- this is not your live view."

---

## 2. UI Interaction Flow

### Happy Path
1. User navigates to Profile Settings > Privacy.
2. User clicks "Preview as..."
3. User selects a perspective: "Not logged in", "Anyone on the platform", or "Specific user."
4. System appends `?view_as=unauthenticated` (or `platform`, or `user:<uuid>`) to the URL.
5. The `ViewAsPlug` parses the perspective in Phase 1 (router pipeline).
6. The controller calls `ViewAsPlug.authorize_view_as(conn, resource_owner_id)` in Phase 2.
7. If authorized, `conn.assigns[:view_as_context]` is set and the view renders as that audience would see it.
8. A persistent amber banner shows the perspective and an "Exit preview" link.
9. User clicks "Exit preview" to return to normal view.

### Sad Paths
- **Invalid perspective**: Phase 1 returns HTTP 422 `{ error: "invalid_perspective" }`.
- **Empty user ID**: `"user:"` returns HTTP 422 `{ error: "invalid_perspective", detail: "user id is required" }`.
- **Group perspective**: `"group:<id>"` returns HTTP 422 `{ error: "not_implemented", detail: "group perspective is not yet supported" }`.
- **Not authorized**: Non-owner, non-platform-owner trying to use ViewAs gets HTTP 403 `{ error: "forbidden" }`.
- **Resource owner using specific user**: Returns HTTP 403 `{ error: "forbidden", detail: "only platform owners may use this perspective" }`.

### Elm State Machine
- **Page module**: `Components.ViewAsBar` renders the preview banner.
- **Model fields involved**: URL query parameter `view_as`.
- **Msg flow**: URL-driven -- no Elm state machine for the perspective itself. The banner is rendered based on URL parsing.

---

## 3. API Calls

ViewAs is implemented as a query parameter on existing content endpoints, not a separate API:

### Any content endpoint with `?view_as=<perspective>`
- **Auth**: Required (JWT Bearer token)
- **Pipeline**: `:api`, `:authenticated`, `:view_as`
- **Plug**: `StacksWeb.Plugs.ViewAsPlug` (Phase 1: parse, Phase 2: authorize in controller)
- **Query param**: `view_as` with values: `unauthenticated`, `platform`, `user:<uuid>`, `group:<uuid>` (not yet supported)
- **Response**: Normal content response filtered by the simulated perspective
- **Error responses**: 422 (invalid/unimplemented perspective), 403 (unauthorized perspective)

---

## 4. Auth & Middleware Guards

### Phase 1: ViewAsPlug.call/2 (router pipeline)
- Parses `?view_as` query parameter.
- Stores parsed perspective in `conn.assigns[:requested_perspective]`:
  - `"unauthenticated"` -> `:unauthenticated`
  - `"platform"` -> `:platform`
  - `"user:<id>"` -> `{:specific_user, id}`
  - `"group:<id>"` -> halts with 422 (not implemented)
  - Invalid -> halts with 422
- Does NOT check ownership at this stage.

### Phase 2: ViewAsPlug.authorize_view_as/2 (controller helper)
- Called by controllers after loading the resource.
- Checks permissions:
  - **Platform owner** (`role: "owner"`): Can use any perspective on any resource (`:unauthenticated`, `:platform`, `{:specific_user, id}`).
  - **Resource owner** (`user.id == resource_owner_id`): Can only use `:unauthenticated` and `:platform` on their own resources.
  - **Others**: 403 Forbidden.
- Sets `conn.assigns[:view_as_context]` on success:
  - `:unauthenticated` -> `:unauthenticated`
  - `:platform` -> `{:platform_user, user.id}`
  - `{:specific_user, id}` -> `{:specific_user, id}` (platform owner only)

## 12. Elm Frontend State Machine (Detail)

### Route
- **Route variant**: Any route with `?view_as` query parameter appended.
- **URL**: e.g., `/bookshelf/library?view_as=unauthenticated`
- **Public or authenticated**: Authenticated (ViewAs requires authentication)

### Init
- `Components.ViewAsBar.view` is rendered on every page. It parses the `view_as` query parameter from the current URL.

### Update cycle
- No dedicated update cycle. The component is stateless -- it reads from the URL.
- "Exit preview" link removes the `view_as` parameter from the URL by reconstructing the query string without it.

### View (Components.ViewAsBar)
- **Key elements**:
  - Amber banner with text "Viewing as: [perspective]"
  - "Exit preview" link that navigates to the same URL without `?view_as`
  - Banner only renders when `view_as` parameter is present in the URL
- **URL parsing**: `getViewAs` extracts the `view_as` value from `url.query` by splitting on `&` and matching `key=value` pairs.
- **URL cleanup**: `removeViewAs` rebuilds the URL path, filtering out the `view_as` parameter from the query string.
- **CSS classes**: `view-as-bar`, `view-as-bar__text`, `view-as-bar__exit`

## 13. Operational Metrics

- **ViewAs usage count**: Total requests with `?view_as` query parameter, segmented by perspective type (`unauthenticated`, `platform`, `user:<id>`). Tracks how often users preview their own content.
- **ViewAs error rate**: Count of 422 (invalid/unimplemented perspective) and 403 (unauthorized) responses from `ViewAsPlug`. High 422 rates may indicate URL construction bugs in the Elm client.
- **Group perspective attempt count**: Count of `"group:<id>"` attempts that return 422 (not implemented). Indicates user demand for group preview functionality.
- **Platform owner vs. resource owner usage**: Segmentation of ViewAs usage by role. Platform owners can use `{:specific_user, id}` perspective; regular users cannot.

---

## 14. Performance & Usability Metrics

- **ViewAs preview load time**: Time to render the page with the simulated perspective applied. ViewAs adds overhead to the standard content load path because `resolve_visibility/2` runs with a synthetic viewer context instead of the real one.
- **ViewAs session duration**: Time between entering a preview (adding `?view_as`) and exiting (clicking "Exit preview"). Indicates how long users spend verifying their visibility settings.
- **Preview accuracy confidence**: No direct metric, but user feedback on whether the preview matched the actual experience of other users. If discrepancies are reported, they indicate bugs in `resolve_visibility/2` or the ViewAs context construction.

---

## 15. Cost Tracking

- ViewAs is a zero-additional-cost feature. It reuses existing content endpoints and visibility resolution logic -- the `?view_as` parameter only changes the viewer context passed to `Visibility.resolve_visibility/2`.
- **Neon**: Same query cost as a normal page load. No additional database operations.
- No external service calls, no storage operations, no email notifications. The only cost is the standard content-serving infrastructure.
