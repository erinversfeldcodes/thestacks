# US-15.2.1 — Navigate Between Sections via the Top Navigation Bar

## 1. User Story

> **As a** user, **I want** a persistent top navigation bar **so that** I can move between my bookshelves, search, upload, and settings from any page.

**Acceptance criteria:**
- The navigation bar appears on every page
- Authenticated users see the full navigation: the five bookshelves (Library, Antilibrary, Wish List, Reading Pile, Looking for a Home), Catalogue/Marketplace/Admin dropdowns, and the user menu (display-name trigger)
- Unauthenticated users see only Catalogue, Marketplace, and Sign In
- All navigation items link to the correct routes defined in `Navigation.Route`
- The active page is visually indicated via `app-nav__item--active`
- The user menu dropdown contains "Settings" and "Sign Out"
- The platform logo links to `/` (no forced redirect for authenticated users in the current implementation; see US-15.1.1)
- The visual treatment follows the dark-academic-meets-cottage-core aesthetic

---

## 2. UI Interaction Flow

### Happy Path
1. The navigation bar is rendered by `viewNav` in Main.elm on every page.
2. The `<header class="app-header">` contains the brand section and the `<nav>` element.
3. Navigation items are rendered as `<li>` elements in a `<ul class="app-nav__list">`.
4. Clicking a nav item triggers a `LinkClicked (Browser.Internal url)` which calls `Nav.pushUrl`. (Special case: clicking a `BookDetail` link opens an overlay rather than navigating — see ADR-005.)
5. `UrlChanged` fires, `initPage` loads the target page, and the nav re-renders with the new active state.

### Authenticated Navigation Items
The five top-level bookshelves are presented as direct nav items (matching the bookshelf vocabulary — these are bookshelves, not "shelves"):
- Library (`/library`)
- Antilibrary (`/antilibrary`)
- Wish List (`/wishlist`)
- Reading Pile (`/reading-pile`)
- Looking for a Home (`/looking-for-home`)

Followed by dropdowns (primary link + sub-items):
- Catalogue dropdown — primary: Catalogue (`/catalogue`); sub-items: Search (`/search`), Add Book (`/upload`)
- Marketplace dropdown — primary: Marketplace (`/marketplace`); sub-items: Create Listing (`/marketplace/create`), My Listings (`/marketplace/mine`)
- Admin dropdown (owner only) — primary: Sources (`/admin/sources`, label "Admin"); sub-items: Sources (`/admin/sources`), Scrapers (`/admin/scrapers`), Book Moderation (`/admin/book-moderation`). (The former Metrics primary at `/admin/metrics` was removed in #267 — the ops-metrics surface is Grafana, not an in-app page.)
- User menu (`UserMenu.view`): the user's display name is the dropdown trigger; menu contains Settings (`/settings/profile`) and Sign Out

### Unauthenticated Navigation Items
- Catalogue (`/catalogue`)
- Marketplace (`/marketplace`)
- Sign In (`/login`)

### Brand Section
- "The Stacks" logo links to `/`
- Dropdown contains "Costs" link to `/costs`

### Active State
- `navItem` compares `currentRoute == targetRoute` and applies `app-nav__item--active`
- `navDropdown` checks primary route and all sub-item routes for active state
- Settings routes use `isSettingsRoute` helper to mark the user menu as active

### Elm State Machine
- **No dedicated page module** — navigation is rendered in `viewNav` within Main.elm.
- **Model fields**: `model.auth`, `model.route`, `model.userMenu`

## 12. Elm Frontend State Machine (Detail)

### Route
- **Route variant**: N/A — The navigation bar is global, not tied to a specific route.

### Init
- **User menu**: `UserMenu.init` -> `{ open = False }`
- **Auth state**: Decoded from flags on app startup.

### Update cycle
- **Msg**: `LinkClicked (Browser.Internal url)` — `Nav.pushUrl model.key (Url.toString url)`. Special case: if target is `BookDetail bookId`, opens overlay instead of navigating.
- **Msg**: `UrlChanged url` — Parses route, calls `initPage`, updates `model.route`, `model.page`, `model.previousRoute`, `model.transition`. Resets `model.userMenu` to `UserMenu.init` on every navigation.
- **Msg**: `UserMenuMsg subMsg` — Delegates to `UserMenu.update`. Handles `NavigateToSettings` (pushes `/settings/profile`) and `SignOut` (clears auth, redirects to `/login`).
- **Msg**: `SettingsMobileNavChanged path` — Used by the settings hub mobile dropdown to navigate between settings sub-pages.
- **Msg**: `EscapePressed` — Closes user menu dropdown if open (via `UserMenu.Close`).

### View
- **`viewNav`**: `<header class="app-header">` containing:
  - Brand: `<div class="app-header__brand app-nav__dropdown">` with logo link and Costs dropdown
  - Nav: `<nav class="app-nav" aria-label="Main navigation">` with `<ul class="app-nav__list">`
  - Items: `navItem` renders `<li class="app-nav__item">` with `<a class="app-nav__link">`
  - Dropdowns: `navDropdown` renders `<li class="app-nav__item app-nav__dropdown">` with nested `<ul class="app-nav__dropdown-menu">`
- **ARIA attributes**: `aria-label="Main navigation"` on `<nav>`, `aria-label="User menu"` on user menu, `aria-expanded` and `aria-haspopup` on user menu trigger.
- **CSS classes**: `app-header`, `app-header__brand`, `app-header__logo`, `app-nav`, `app-nav__list`, `app-nav__item`, `app-nav__item--active`, `app-nav__link`, `app-nav__dropdown`, `app-nav__dropdown-menu`, `app-nav__dropdown-link`, `app-nav__user`, `app-nav__logout`

## 13. Operational Metrics

- **Navigation click distribution**: Count of clicks per navigation item (Library, Antilibrary, Wish List, Reading Pile, Looking for a Home, etc.) to understand user navigation patterns across bookshelves and dropdowns.
- **Dropdown open rate**: How often users open the Catalogue, Marketplace, Admin, and User Menu dropdowns.
- **User menu action distribution**: Ratio of "Settings" clicks to "Sign Out" clicks from the user menu dropdown.
- **Mobile vs desktop navigation usage**: Navigation interaction breakdown by device type.
- **Active state accuracy**: Verification that `app-nav__item--active` correctly reflects the current route (testing/monitoring concern).

---

## 14. Performance & Usability Metrics

- **Navigation render time**: Time for `viewNav` to produce its virtual DOM. Should be <5ms (no API calls, pure view function).
- **Route transition time**: Time from `LinkClicked` to `UrlChanged` completion (includes `initPage` for the target page).
- **Dropdown interaction time**: Time from dropdown trigger click to item selection. Long times may indicate difficulty finding items.
- **Mobile navigation effectiveness**: Task completion rate on mobile (can users find and reach all sections?).
- **Keyboard navigation coverage**: All nav items are `<a>` elements (naturally focusable). Verify Tab order reaches all items.
- **Settings route detection**: `isSettingsRoute` helper accuracy — does the user menu show as active on all settings sub-pages?
