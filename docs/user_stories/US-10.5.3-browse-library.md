# US-10.5.3 — Browse a Reader's Bookshelf

> The per-book consumer of the visibility model. Where US-10.5.2 lists which
> shelves a viewer may see, this story renders the books *on* a shelf, filtered
> per-placement — so placement visibility (US-10.2.2) and age-gating (US-1.1.4)
> become observable to a viewing reader. Read-only: a viewer can look, not touch.

## 1. User Story

**As a** reader, **I want to** browse another reader's bookshelf at
`/u/:handle/:bookshelf_name` **so that** I can see the books they've shared,
exactly as their visibility settings permit — no more, no less.

### Acceptance criteria — the placement visibility matrix

`GET /api/u/:handle/bookshelves/:bookshelf_name` gates at two levels:

**Bookshelf level** (`resolve_visibility(bookshelf, viewer)`): hidden → **404**.
Ghost profile → 404. Invalid bookshelf name → 404.

**Per-placement** (`ProtoJSON.shelf_with_placements(shelf, viewer)`), each book:

| Placement visibility → / Viewer ↓ | **platform** | **group** | **owner** |
|---|---|---|---|
| Owner (self) | shown | shown | shown |
| Authenticated non-owner, group **member** | shown | shown | hidden |
| Authenticated non-owner, **non-member** | shown | hidden | hidden |
| Unauthenticated | shown | hidden | hidden |

**Age gate** (orthogonal, applied on top): an `age_gated` book is **hidden** from
an unauthenticated or non-age-verified viewer, and shown to an age-verified one —
regardless of the placement's audience.

- The response `count` reflects only the visible placements.
- The view is **read-only**: no move/edit/visibility/remove controls, and no
  mutating requests are wired.

## 2. UI Interaction Flow

### Happy path
From a profile hub (US-10.5.2), tap a shelf → the shelf renders like the owner's
own view but read-only: spines for the visible books only.

### Sad paths
- Hidden shelf / ghost / bad name → "Reader not found" (or an empty/── not-available state); no leak of what exists.

### Elm state machine
`Page.Bookshelf` in a `readOnly` config: same fetch/render, mutating Msgs and controls stripped; fetch URL is `/api/u/:handle/bookshelves/:name`.

## 3. API Calls

### `GET /api/u/:handle/bookshelves/:bookshelf_name` → `ProfileController.shelf`
`:optional_auth`. Validates the bookshelf name (404 otherwise); ghost/block gate; `resolve_visibility(bookshelf, viewer)` → 404 if hidden; else maps `get_bookshelf_shelves(target.id, name)` through `shelf_with_placements(&1, viewer)`.

## 4. Auth & Middleware Guards
`:optional_auth`. Viewer identity determines the filter; the resolver is the boundary. (SECURITY) cross-user leakage is the highest-value sad path — a non-member must never see a `group`/`owner` placement.

## 5. Database Interactions
- `Shelving.get_bookshelf(target.id, name)` + `get_bookshelf_shelves(target.id, name)` (both already take an arbitrary user id).
- Per-placement `resolve_visibility/2` (profile ceiling + block + age gate + group membership).

## 12. Elm Frontend State Machine (Detail)
- **Route**: `Route.ProfileShelf String String` = `/u/:handle/:bookshelf_name`.
- **Config**: `Page.Bookshelf` gains a `readOnly`/`editable` flag + a parameterised fetch URL; when read-only, the visibility control, move, and remove affordances are omitted and their Msgs dropped.
- **View**: the spine grid, read-only. An `owner`-only book of the target's is simply absent (not a faint spine — that faint-spine affordance is the *owner's own* view).
