# US-12.2.2 — Manage Writing Assistant Data

## 1. User Story

> **As a** user, **I want to** view and manage my writing assistant session history **so that** I understand what data is being used to personalise my experience and can delete it if I choose.

The user navigates to Settings > Writing Assistant. They see a list of sessions — one per post — with the post title, date of last activity, and turn count. They can delete individual sessions. A link to the consent toggle (US-8.3) is present. Transparent copy explains what data is used and how.

**Acceptance criteria:**
- [ ] `/settings/writing-assistant` renders for authenticated users with `consent_writing_assistant = true`
- [ ] Sessions listed with post title, last active date, turn count
- [ ] Individual session deletable with confirmation
- [ ] Deleting a session removes it and its associated turn_feedback and retrieval_log entries
- [ ] If no sessions exist, an appropriate empty state renders
- [ ] Link to Privacy & Consent settings visible
- [ ] If `consent_writing_assistant = false`, page shows disabled state with link to enable

---

## 2. UI Interaction Flow

### Happy Path
1. User navigates to Settings > Writing Assistant (via settings sidebar).
2. Page sends `GET /api/writing-assistant/sessions`.
3. Sessions render as a list: post title, last active date, turn count.
4. User clicks "Delete" on a session.
5. Confirmation: "Delete this conversation? This cannot be undone."
6. User confirms → `DELETE /api/writing-assistant/sessions/:id`.
7. Session removed from list. "Conversation deleted." confirmation.

### Sad Paths
- **No sessions**: Empty state: "You haven't used the writing assistant yet. [Open the blog editor to get started.]"
- **Consent not granted**: Page shows: "The writing assistant is currently turned off. [Enable in Privacy & Consent]" — no sessions listed.
- **Delete failure**: "Could not delete conversation. Please try again."
- **Load failure**: "Could not load your writing assistant history. Please try again."

### Elm State Machine
- **Page module**: `Page.Settings.WritingAssistant`
- **Model fields involved**:
  - `sessions : RemoteData Http.Error (List SessionSummary)`
  - `deleting : Dict String (RemoteData Http.Error ())`
  - `confirmingDelete : Maybe String` — session ID awaiting confirmation
  - `consentGranted : Bool`
- **Msg flow**:
  - `SessionsLoaded (Ok sessions)` → `sessions = Success sessions`
  - `SessionsLoaded (Err err)` → `sessions = Failure err`
  - `RequestDeleteSession id` → `confirmingDelete = Just id`
  - `CancelDelete` → `confirmingDelete = Nothing`
  - `ConfirmDeleteSession id` → fires `Api.deleteAssistantSession id`, sets `deleting[id] = Loading`, `confirmingDelete = Nothing`
  - `DeleteCompleted id (Ok _)` → removes session from list, `deleting[id] = Success ()`
  - `DeleteCompleted id (Err err)` → `deleting[id] = Failure err`
- **RemoteData states**: `sessions`: `Loading → Success/Failure`; per-session `deleting`: `NotAsked → Loading → Success/Failure`

## 3. API Calls

### `GET /api/writing-assistant/sessions`
- **Auth**: Required (JWT Bearer token)
- **Pipeline**: `:api`, `:authenticated`
- **Controller**: `StacksWeb.WritingAssistantController.list_sessions/2`
- **Response (success)**: `{ sessions: [{ id, post_id, post_title, turn_count, last_active_at }] }` — HTTP 200
- **Response (empty)**: `{ sessions: [] }` — HTTP 200
- **Response (error)**: 401 without auth

### `DELETE /api/writing-assistant/sessions/:id`
- **Auth**: Required (JWT Bearer token)
- **Pipeline**: `:api`, `:authenticated`
- **Controller**: `StacksWeb.WritingAssistantController.delete_session/2`
- **Response (success)**: `{ deleted: true }` — HTTP 200
- **Response (error)**:
  - `{ error: "not_found" }` — HTTP 404
  - `{ error: "unauthorized" }` — HTTP 403 (session belongs to another user)

---

## 4. Auth & Middleware Guards

- **Plugs fired** (in order): `SecurityHeaders` → `AuthPipeline` (`:authenticated`) → controller action
- **Visibility checks**: Sessions are always owner-only. `list_sessions/2` filters by `user_id = current_user.id`. `delete_session/2` verifies `session.user_id == current_user.id` before deletion.
- **Age gate**: N/A
- **Ownership checks**: `check_session_ownership/2` in controller — returns 403 if session belongs to another user

## 5. Database Interactions

### Read: List sessions for user
- **Table(s)**: `op.blog_assistant_sessions`, `op.blog_posts`
- **Query**: `from s in BlogAssistantSession, join: p in BlogPost, on: p.id == s.post_id, where: s.user_id == ^user_id, select: %{ id: s.id, post_id: s.post_id, post_title: p.title, turn_count: fragment("jsonb_array_length(?)", s.turns), last_active_at: s.last_active_at }, order_by: [desc: s.last_active_at]`
- **Schema module**: `Stacks.AI.BlogAssistantSession`

### Write: Delete session
- **Table(s)**: `op.blog_assistant_sessions`, `op.turn_feedback`, `op.retrieval_log`
- **Operation**: DELETE
- **Transaction**: `Ecto.Multi` — explicit delete of `turn_feedback` and `retrieval_log` records, then session delete (or cascade via FK if configured)
- **Changeset validations**: Ownership verified before delete
- **Schema module**: `Stacks.AI.BlogAssistantSession`

## 12. Elm Frontend State Machine (Detail)

### Route
- **Route variant**: `Route.SettingsWritingAssistant`
- **URL**: `/settings/writing-assistant`
- **Public or authenticated**: Authenticated

### Init
- **`initPage` branch**: `Page.Settings.WritingAssistant.init maybeToken user`
- **API calls on init**: If `user.consent_writing_assistant == true` → `Api.getAssistantSessions token SessionsLoaded`; if false → no API call
- **Initial model state**:
  - `sessions = if consentGranted then Loading else NotAsked`
  - `deleting = Dict.empty`
  - `confirmingDelete = Nothing`
  - `consentGranted = user.consent_writing_assistant`

### Update cycle
- **Msg**: `SessionsLoaded (Ok sessions)` → `sessions = Success sessions`
- **Msg**: `SessionsLoaded (Err err)` → `sessions = Failure err`
- **Msg**: `RequestDeleteSession id` → `confirmingDelete = Just id`
- **Msg**: `CancelDelete` → `confirmingDelete = Nothing`
- **Msg**: `ConfirmDeleteSession id` → sets `deleting = Dict.insert id Loading deleting`, fires `Api.deleteAssistantSession id token (DeleteCompleted id)`, `confirmingDelete = Nothing`
- **Msg**: `DeleteCompleted id (Ok _)` → removes session with `id` from `sessions` list, `deleting = Dict.insert id (Success ()) deleting`
- **Msg**: `DeleteCompleted id (Err err)` → `deleting = Dict.insert id (Failure err) deleting`

### View
- **Wrapped in**: `viewSettingsHub` layout (same as other settings pages)
- **Consent not granted state**: Callout block — "The writing assistant is currently turned off." with link to `/settings/consent`
- **Loading state**: Spinner or skeleton list
- **Empty state**: "You haven't used the writing assistant yet." with link to blog editor
- **Session list**: Each row shows:
  - Post title (linked to `/blog/posts/:id`)
  - Last active date (relative: "2 days ago")
  - Turn count ("4 turns")
  - Delete button (ghost style, opens confirmation)
- **Confirmation modal**: "Delete this conversation? This cannot be undone." with Delete / Cancel buttons
- **Deleting state**: Row shows spinner while `deleting[id] = Loading`
- **Transparency section** (below list): "The writing assistant uses your shelf and writing history to personalise suggestions. It does not share your data. [Manage consent]"
- **CSS classes**: `page--settings`, `settings-section`, `writing-assistant-sessions`, `writing-assistant-sessions__row`, `writing-assistant-sessions__title`, `writing-assistant-sessions__meta`, `writing-assistant-sessions__delete`, `writing-assistant-sessions__empty`, `writing-assistant-sessions__consent-callout`

## 13. Operational Metrics

- **Session list load latency**: round-trip time for `GET /api/writing-assistant/sessions` — includes JOIN with `op.blog_posts` and `jsonb_array_length` computation
- **Session delete count**: total `writing_assistant.session_deleted` events; tracks how often users exercise this right
- **Sessions per user distribution**: average and p95 session count; informs pagination decision
- **Consent page navigation rate**: how often users click the "Manage consent" link from this page

---

## 14. Performance & Usability Metrics

- **Page load time**: time from navigation to session list rendered — dominated by `GET /api/writing-assistant/sessions` query
- **Delete confirmation friction**: time between "Delete" click and confirmation submit — if very long, users may be reading the modal carefully (expected)
