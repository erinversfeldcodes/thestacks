# US-15.3.1 — View the Platform Footer

## 1. User Story

> **As a** user, **I want** a simple footer on every page **so that** I can see basic platform information and know I have reached the bottom of the page content.

**Acceptance criteria:**
- The footer appears on every page (rendered globally in `view` after `viewPage`)
- The footer displays the platform tagline: "The Stacks — open source book management"
- The footer is visually consistent with the dark-academic-meets-cottage-core aesthetic established by CLAUDE.md

---

## 2. UI Interaction Flow

### Happy Path
This is automatic — the footer renders at the bottom of every page.

1. `viewFooter` is called in the `view` function of Main.elm, after `viewPage`.
2. A `<footer class="app-footer">` renders with the tagline.

### Elm State Machine
- **No dedicated module** — `viewFooter` is a function in Main.elm.
- **No model, no messages, no state.**

## 12. Elm Frontend State Machine (Detail)

### Route
N/A — The footer is global, rendered on every page regardless of route.

### View
- **`viewFooter`**:
  ```elm
  footer [ class "app-footer" ]
      [ p [ class "app-footer__text" ]
          [ text "The Stacks — open source book management" ]
      ]
  ```
- **ARIA attributes**: None — the `<footer>` element has implicit landmark semantics.
- **CSS classes**: `app-footer`, `app-footer__text`
- **Position**: Rendered after `main_` in the `div.app` container.

## 13. Operational Metrics

- **Footer render rate**: The footer renders on every page load — count equals total page views. No independent metric needed.
- **Footer visibility**: Percentage of page views where the user scrolls far enough to see the footer (requires scroll tracking, not currently implemented).

---

## 14. Performance & Usability Metrics

- **Footer render time**: Negligible — `viewFooter` is a static function with no model, no messages, no API calls. <1ms render time.
- **Footer as scroll landmark**: Whether users use the footer appearance as confirmation they have reached the bottom of page content.
- **Content completeness signal**: The footer's presence confirms the page has fully rendered (useful as a visual integration test anchor).
