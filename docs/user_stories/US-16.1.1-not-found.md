# US-16.1.1 — View the 404 Not Found Page

## 1. User Story

> **As a** user who has navigated to a URL that does not exist, **I want to** see a clear, friendly error page **so that** I understand the page was not found and can navigate back to a valid part of the platform.

**Acceptance criteria:**
- Any unrecognised URL renders the not-found page instead of a blank screen or browser error
- The page displays a heading, explanation, and a link to the home page
- The global navigation and footer remain visible
- The browser tab title updates to "Not Found — The Stacks"

---

## 2. UI Interaction Flow

### Happy Path
1. User navigates to any URL that does not match a known route (e.g., `/nonexistent-page`).
2. `Route.fromUrl url` calls `Parser.parse parser url`. No parser matches, so `Maybe.withDefault NotFound` returns `NotFound`.
3. `initPage NotFound _ _` -> `( PageNotFound, Cmd.none )`.
4. `viewNotFound` renders the error page.
5. The navigation bar and footer remain visible (they are rendered by the global `view` function regardless of page content).

### Elm State Machine
- **No dedicated page module** — `viewNotFound` is an inline function in Main.elm.
- **No model, no messages** — `PageNotFound` is a model-less page variant.

## 4. Auth & Middleware Guards

- **Client-side routing**: The Elm router handles all URL parsing. The server-side catch-all route (`get "/*path", PageController, :index`) serves the SPA HTML for any path, so the server never returns a 404 for page navigation.
- **Auth check**: `requiresAuth NotFound` returns `False`, so the 404 page renders regardless of auth state.

## 12. Elm Frontend State Machine (Detail)

### Route
- **Route variant**: `Route.NotFound`
- **URL**: Any URL not matched by the parser (e.g., `/nonexistent-page`)
- **Public or authenticated**: Public (`requiresAuth NotFound` returns `False`)
- **`toPath NotFound`**: Returns `"/not-found"` (but this is only used for programmatic navigation, not route matching)

### Init
- **`initPage` branch**: `NotFound -> ( PageNotFound, Cmd.none )`
- **API calls on init**: None

### View
- **`viewNotFound`**:
  ```elm
  div [ class "page page--not-found" ]
      [ h1 [] [ text "Page Not Found" ]
      , p [] [ text "The page you're looking for doesn't exist." ]
      , a [ href "/", class "btn btn--primary" ] [ text "Go Home" ]
      ]
  ```
- **Browser tab title**: `"Not Found — The Stacks"` (via `pageTitle NotFound`)
- **ARIA attributes**: None specific to this page. Standard heading hierarchy applies.
- **CSS classes**: `page`, `page--not-found`, `btn`, `btn--primary`
- **Layout**: Navigation and footer are visible (rendered in the parent `view` function).

## 13. Operational Metrics

- **404 hit rate**: Count of `Route.NotFound` renders per day. Spikes indicate broken links, crawler activity, or user-facing URL issues.
- **404 source URLs**: Track the URLs that resolve to NotFound to identify common broken paths or mistyped URLs.
- **Referrer analysis**: Where 404 traffic originates — internal broken links vs external/search engine links.
- **Exit rate from 404**: Percentage of users who leave the site after seeing the 404 page vs clicking "Go Home".

---

## 14. Performance & Usability Metrics

- **404 page render time**: Time from URL parse to page render. Should be <50ms (static page, no API calls, no model).
- **Recovery rate**: Percentage of users who click "Go Home" and continue using the platform vs abandoning the session.
- **Time-on-404-page**: Average dwell time. Very short times suggest users quickly recover; very long times suggest confusion.
- **Repeat 404 rate**: How often the same user hits 404 pages in a session. Indicates navigation confusion.
