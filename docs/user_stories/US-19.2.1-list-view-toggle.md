# US-19.2.1 — List View Toggle

## 1. User Story

> **As a** user, **I want** an alternative list view for my bookshelves **so that** I can browse my collection in a format that is more accessible, more information-dense, or better suited to certain screen sizes.

**Acceptance criteria:**
- A list/grid toggle is visible on all bookshelf pages
- List view displays books as sortable rows with key metadata
- The view preference persists across page navigation and sessions (not yet implemented — currently per-page-load only)
- Clicking a row opens the book detail overlay
- The toggle is keyboard-accessible
- List view is the default for screen reader users (not yet implemented)

---

## 2. UI Interaction Flow

### Happy Path
1. On any bookshelf page, the user clicks the "List view" toggle button (next to the "Spine view" toggle).
2. The view switches from the visual spine bookshelf to a structured table.
3. The table shows columns: Title, Author, Pages, Date Added, Formats.
4. Columns are sortable — clicking a column header toggles sort direction.
5. Clicking a row fires the `onBookClicked` handler, opening the book detail overlay.

### Toggle Behaviour
- Two toggle buttons in a `role="group"` with `aria-label="View mode"`.
- Each button has `aria-pressed="true"/"false"` and `aria-label="Spine view"/"List view"`.
- Active button gets `view-mode-toggle__btn--active` class.

### Sort Behaviour
- Default sort: `Title` ascending.
- Clicking a column header cycles: no sort -> ascending -> descending.
- `aria-sort` attribute on each `<th>`: `"ascending"`, `"descending"`, or `"none"`.
- Visual sort indicator: `" ^"` for ascending, `" v"` for descending.

### Elm State Machine
- **Toggle component**: `Components.ViewModeToggle`
  - Type: `ShelfViewMode = SpineView | ListView`
  - View function takes: current mode, toggle handler
- **List component**: `Components.BookList`
  - Model: `SortState = { column : SortColumn, direction : SortDirection }`
  - `SortColumn = Title | Author | PageCount | DateAdded | Formats`
  - `SortDirection = Asc | Desc`
  - View function takes: sort state, sort handler, book click handler, placements list

## 12. Elm Frontend State Machine (Detail)

### Route
N/A — The view mode toggle is a component used within bookshelf pages, not a route.

### ViewModeToggle Component
- **Type**: `ShelfViewMode = SpineView | ListView`
- **View**: `view : ShelfViewMode -> (ShelfViewMode -> msg) -> Html msg`
- Renders two buttons in a `div.view-mode-toggle`:
  - Spine view button: text `"|||"`, `aria-label="Spine view"`, `aria-pressed`
  - List view button: text `"="`, `aria-label="List view"`, `aria-pressed`

### BookList Component
- **Types**:
  - `SortColumn = Title | Author | PageCount | DateAdded | Formats`
  - `SortDirection = Asc | Desc`
  - `SortState = { column : SortColumn, direction : SortDirection }`
- **View**: `view : SortState -> (SortColumn -> msg) -> (Book -> msg) -> List Placement -> Html msg`
- Renders `table.book-list` with `role="table"`:
  - `<thead>` with sortable column headers (`scope="col"`, `aria-sort`, click handler)
  - `<tbody>` with rows, each as `tr.book-list__row` with `role="row"`, click handler
  - Columns: Title, Author, Pages (from `bookPageCount`), Date Added (first 10 chars of `placedAt`), Formats (badges)
- **Sort logic**: `sortPlacements` sorts by the active column using `List.sortWith`, reverses for `Desc`.
- **Format badges**: `span.book-list__format-badge` for each format (Physical, eBook, Audiobook).
- **Fallback data**: If a placement's `book` is `Nothing`, displays "Unknown Title" / "Unknown Author".

### CSS Classes
- Toggle: `view-mode-toggle`, `view-mode-toggle__btn`, `view-mode-toggle__btn--active`
- Table: `book-list`, `book-list__row`, `book-list__sort-indicator`, `book-list__formats`, `book-list__format-badge`

## 13. Operational Metrics

- **View mode distribution**: Percentage of bookshelf page views in Spine view vs List view. Indicates user preference.
- **Toggle switch rate**: Count of view mode toggles per session. Frequent switching may indicate neither view is satisfactory.
- **Sort usage rate**: Percentage of List view sessions where the user clicks a column header to sort.
- **Sort column distribution**: Which columns are sorted most frequently (Title, Author, Pages, Date Added, Formats).
- **Sort direction preference**: Ratio of ascending to descending sorts per column.
- **List view book click rate**: Percentage of list view sessions where the user clicks a row to open the detail overlay.

---

## 14. Performance & Usability Metrics

- **Toggle responsiveness**: Time from toggle click to view mode change. Should be <16ms (synchronous Elm model update, no API call).
- **List view render time**: Time to render the `BookList` table for large collections. Scales linearly with placement count — monitor for collections >500 books.
- **Sort performance**: Time for `sortPlacements` to sort the list. Should be <50ms for typical collection sizes. For large collections (>1000), consider if sorting lag is noticeable.
- **Keyboard accessibility of toggle**: Both toggle buttons have `aria-pressed` and `aria-label`. Verify Tab + Enter/Space activates the toggle.
- **Screen reader compatibility**: `role="table"`, `scope="col"`, `aria-sort` on headers, `role="row"` on data rows. Verify screen readers announce sort state and table structure correctly.
- **View preference persistence gap**: Currently view mode resets to spine view on every page navigation. Track how often users switch to list view (indicates demand for persistence).
- **Format badge readability**: Whether format badges (Physical, eBook, Audiobook) are announced correctly by screen readers.

---

## 15. Cost Tracking

- **No server-side costs**: List view uses the same placement data already loaded by the bookshelf API call. No additional API calls, no database reads.
- **Client-side compute**: Sorting runs in the browser. For typical collection sizes (<500 books), negligible. For very large collections, sorting is O(n log n) in Elm — still negligible on modern devices.
- **View preference persistence (future)**: If implemented as a user preference, would require one additional DB write. Negligible cost.
- **Total cost**: $0.00 (no additional server-side work beyond the bookshelf data load).
