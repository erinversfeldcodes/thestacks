# US-10.4.1 — Search Engine Privacy

## 1. User Story

> **As a** user, **I want to** know that my profile and reading history will never appear in search engine results **so that** my presence on the platform remains private from the wider internet.

No user action required -- this is a platform-wide guarantee enforced automatically.

**What the platform does:**
- All user-generated pages include `<meta name="robots" content="noindex, nofollow">`.
- `robots.txt` disallows all crawlers from user profile, shelf, and post URLs.
- Unauthenticated requests to any user-data endpoint return no personal data -- they receive either a redirect to the login page or an empty response.

**What they see:**
- In Privacy Settings, a single line: "Your profile and content will never appear in search engine results. This applies to all users and cannot be changed."

---

## 2. UI Interaction Flow

### Happy Path
No user interaction. This is a platform guarantee.

1. Search engine crawler requests a user profile or shelf URL.
2. `robots.txt` instructs the crawler not to index.
3. Even if the crawler ignores `robots.txt`, the page meta tag reinforces `noindex, nofollow`.
4. Even if the crawler bypasses meta tags, the API returns no personal data for unauthenticated requests.

### Sad Paths
N/A -- There is no user-configurable setting. The protection is always on.

### Elm State Machine
N/A -- No frontend state machine for this feature. The meta tag is rendered at the HTML template level, not in Elm.

---

## 3. API Calls

### Unauthenticated API requests
- All user-data API endpoints (shelves, posts, placements) use `Guardian.Plug.current_resource(conn)` to identify the viewer.
- When `current_resource` returns `nil`, the viewer is `:unauthenticated`.
- `Stacks.Visibility.resolve_visibility/2` with `:unauthenticated` viewer:
  - Resources with `visibility: "owner"` -> `:hidden`
  - Resources with `visibility: "group"` -> `:hidden`
  - Resources with `visibility: "platform"` -> `:visible` (but only for authenticated platform users; unauthenticated gets `:ok` from the resource check but may be blocked by profile ceiling)
  - Profile ceiling `"owner"` -> `:hidden` for all non-owner viewers including unauthenticated

---

## 4. Auth & Middleware Guards

- **Static HTML shell**: `apps/core/priv/static/index.html` declares `<meta name="robots" content="noindex, nofollow" />` at the document head, so every SPA route inherits it. (The `StacksWeb.Plugs.SecurityHeaders` plug sets HTTP security headers -- CSP, HSTS, frame-options, etc. -- but does not inject the robots meta tag.)
- **robots.txt**: Served via `Plug.Static` from `apps/core/priv/static/`, disallowing crawlers from user content paths.
- **Visibility resolution**: `Stacks.Visibility.resolve_visibility/2` provides the backend enforcement:
  - Unauthenticated viewers cannot see `"owner"` or `"group"` visibility resources.
  - Profile ceiling of `"owner"` hides everything from unauthenticated.
  - Even `"platform"` visibility resources are functionally hidden from search engines because authenticated session is required.

## 13. Operational Metrics

- **Crawler request count**: Total requests to user-content paths from known search engine crawlers (identified by User-Agent). Confirms that `robots.txt` is being respected -- or not.
- **robots.txt fetch count**: Requests to `/robots.txt`. Healthy crawlers fetch this periodically; a complete absence may indicate configuration issues.
- **Unauthenticated content request count**: Total unauthenticated requests to user-data API endpoints (shelves, posts, placements). These should all return empty/hidden results, confirming the third layer of defence.

---

## 14. Performance & Usability Metrics

- **Meta tag presence verification**: Periodic check that `<meta name="robots" content="noindex, nofollow">` is present in all user-generated page HTML responses. A regression here would silently expose content to search engines.
- **robots.txt correctness verification**: Periodic check that `robots.txt` disallows crawlers from user profile, shelf, and post URL patterns. Should be part of the CI/CD pipeline or health check suite.
- No user-facing performance metrics since there is no user interaction. This feature is entirely passive enforcement.

---

## 15. Cost Tracking

- This feature has zero incremental cost. The `noindex` meta tag and `robots.txt` are static responses served by the web server.
- **Neon**: No database operations. The robots meta tag is baked into the static `index.html` shell served by `Plug.Static`. The visibility resolution that hides content from unauthenticated users is the same logic used for all content access -- no additional queries.
- No external service calls, no storage operations, no email notifications. The enforcement is purely middleware-level.
