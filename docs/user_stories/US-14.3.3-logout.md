# US-14.3.3 — Log Out

## 1. User Story

> **As an** authenticated user, **I want to** sign out of The Stacks **so that** my session is ended and my personal data is no longer accessible from this browser.

**Acceptance criteria:**
- The display name dropdown contains "Settings" and "Sign Out"
- "Settings" navigates to `/settings`
- Clicking "Sign Out" removes the JWT from localStorage via the `clearAuth` port
- The Elm model's `auth` field is set to `Nothing`, clearing all personal data from application state
- The user is redirected to the sign-in page after signing out
- After signing out, navigating to a protected page redirects to sign-in
- The sign-out action works in both normal and private browsing sessions

---

## 2. UI Interaction Flow

### Happy Path
1. User clicks their display name in the top navigation bar.
2. A dropdown appears with two items: "Settings" and "Sign Out".
3. User clicks "Sign Out".
4. The `UserMenu` component emits `SignOut` OutMsg.
5. Main.elm handles the OutMsg:
   - Sets `model.auth = Nothing`
   - Sets `model.page = PageLogin Login.init`
   - Calls `Api.logout auth.token` (POST to `/api/auth/logout` to revoke the server-side token)
   - Calls `clearAuth ()` port (clears localStorage)
   - Navigates to `/login`
6. Navigation reverts to unauthenticated state.

### Sad Paths
- **Logout API call fails**: The client still clears local auth state and redirects. Server-side token revocation failure is non-blocking — the token will expire naturally.
- **Click outside dropdown**: Invisible full-screen backdrop (`user-menu__backdrop`) catches the click, closes the dropdown via `Close` msg.
- **Escape key**: Global `EscapePressed` handler in Main.elm closes the user menu via `UserMenu.Close`.

### Elm State Machine
- **Component module**: `Components.UserMenu`
- **Model fields**: `open : Bool`
- **Msg flow**: `Toggle` -> opens/closes dropdown; `SignOutClicked` -> closes dropdown, emits `SignOut` OutMsg.
- **OutMsg pattern**: `SignOut` -> Main handles by clearing auth, calling APIs/ports, redirecting.

---

## 3. API Calls

### `DELETE /api/auth/logout`
- **Auth**: Required (Bearer JWT)
- **Pipeline**: `:api`, `:authenticated`
- **Controller**: `StacksWeb.AuthController.logout/2`
- **Request body**: None
- **Response**: HTTP 204 No Content
- **What it does**: Calls `Guardian.revoke(token)` to invalidate the JWT server-side.
- **Note**: The Elm `Api.logout` function uses `method = "POST"` but the router defines this as `delete "/auth/logout"`. This is a potential mismatch — the POST may get a 404 from the router. The client-side auth clearing works regardless.

## 4. Auth & Middleware Guards

- **Plugs fired**: `SecurityHeaders` -> `AuthPipeline` (VerifyHeader, EnsureAuthenticated, LoadResource, RequireConfirmedEmail)
- **Token revocation**: `Guardian.revoke/1` invalidates the token (implementation depends on Guardian's token storage strategy — typically uses GuardianDb or in-memory).

## 12. Elm Frontend State Machine (Detail)

### Route
- **Route variant**: N/A — logout is triggered from a component, not a route.
- **Post-logout route**: `Route.Login` (`/login`)

### Update cycle (Main.elm)
- **Msg**: `UserMenuMsg subMsg` when `subMsg` resolves to `SignOutClicked`
- **UserMenu.update**: Returns `( { model | open = False }, SignOut )`
- **Main.elm handling**:
  ```
  UserMenu.SignOut ->
      model.auth = Nothing
      model.page = PageLogin Login.init
      Cmd.batch:
        1. Api.logout auth.token (always LogoutCompleted)  -- fire-and-forget
        2. clearAuth ()  -- clear localStorage
        3. Nav.pushUrl model.key (Route.toPath Login)  -- redirect
  ```
- **Msg**: `LogoutCompleted` — no-op (`( model, Cmd.none )`)

### View (UserMenu component)
- **Trigger button**: `user-menu__trigger app-nav__link app-nav__user` — shows `user.displayName`, has `aria-expanded` and `aria-haspopup="true"`.
- **Dropdown**: `user-menu__dropdown app-nav__dropdown-menu` — contains "Settings" (`app-nav__dropdown-link`) and "Sign Out" (`app-nav__dropdown-link app-nav__logout`).
- **Backdrop**: Invisible full-screen div (`user-menu__backdrop`) with `position: fixed`, `z-index: 999`, catches clicks to close the dropdown.
- **ARIA**: `aria-label="User menu"` on container, `aria-expanded` toggles with open state.

## 13. Operational Metrics

- **Logout request rate**: Count of `DELETE /api/auth/logout` requests per day.
- **Logout success rate**: Ratio of HTTP 204 responses to total logout requests. Failures are non-blocking but indicate Guardian revocation issues.
- **Token revocation success rate**: Percentage of `Guardian.revoke/1` calls that succeed. Failures mean tokens remain valid until natural TTL expiry.
- **Client-side auth clear rate**: Port `clearAuth` invocations — should match logout request rate exactly. Discrepancies indicate port failures.
- **HTTP method mismatch rate**: If the Elm `Api.logout` uses POST but the router expects DELETE, track 404 responses on `POST /api/auth/logout`. This is a known potential issue documented in section 3.
- **Post-logout navigation verification**: Count of API requests from a session after logout (should be zero — any requests indicate incomplete auth clearing).

---

## 14. Performance & Usability Metrics

- **Logout time (click to login page)**: Client-side measurement from "Sign Out" click to `/login` page render. Should be <100ms (no blocking API calls — logout is fire-and-forget).
- **Logout initiation rate**: Percentage of sessions that end with an explicit logout vs token expiry or browser close. Higher explicit logout rates indicate good security hygiene.
- **User menu open-to-logout time**: Duration from user menu dropdown open to "Sign Out" click. Long durations may indicate difficulty finding the option.
- **Post-logout protected page access attempts**: Count of attempts to navigate to protected pages after logout. Should result in clean redirect to login.
- **Escape key vs click-outside dropdown close rate**: How users close the dropdown without selecting an action.

---

## 15. Cost Tracking

- **Guardian token revocation**: One in-memory or DB operation (depends on Guardian storage strategy). Negligible cost.
- **No external service calls**: Logout does not involve Resend, vision, or any external APIs.
- **Database writes**: None (unless GuardianDb is configured, in which case one UPDATE to mark the token as revoked).
- **Fly.io compute**: Minimal — one HTTP request handler invocation.
- **Total per-logout cost**: ~$0.00 (negligible compute, no external services).
