# US-12.1.1 — Write a Blog Post

## 1. User Story

> **As a** user, **I want to** write and publish native blog posts on the platform **so that** I can share my thoughts on reading, books, and ideas with my audience.

From their profile, the user navigates to "Writing" > "New Post." They write in a minimal rich-text editor: title, body (with basic formatting). They set visibility before publishing (see US-10.2.3). They click "Publish." The post is timestamped and appears in their writing archive.

**What they see on the page:**
- The editor is clean and distraction-free: white or parchment background, serif typeface.
- A word count appears subtly at the bottom.
- The publish bar at the bottom contains: visibility selector, a "Save Draft" button, and a "Publish" button.
- A collapsible writing assistant panel sits to the right of the editor (see US-12.2.1). A small pulsing dot on the assistant icon indicates when a proactive nudge is available. The panel does not open automatically — the user opens it at their own pace.
- If the assistant has an unresolved observation at publish time, a non-blocking prompt appears: "There's something unresolved here — publish anyway?"
- Published posts appear on the user's profile under "Writing", displayed as a vertical list of cards.

---

## 2. UI Interaction Flow

### Happy Path
1. User navigates to blog archive page.
2. Clicks "New Post" link (visible only to authenticated users).
3. Blog editor loads with empty title, body, visibility defaulting to "Only me" (owner).
4. User types a title and body.
5. User optionally selects visibility (owner / group / platform).
6. User clicks "Save Draft" -- system creates the post via `POST /api/blog/posts`.
7. On success, editor mode switches from `New` to `Edit postId`.
8. User clicks "Publish" -- system saves first, then publishes via `POST /api/blog/posts/:id/publish`.
9. On publish success, `blog.post_published` event is emitted, triggering the LLM book association job.

### Sad Paths
- **Save failure**: Elm shows "Could not save post. Please try again." `saving` transitions to `Failure`.
- **Publish failure**: Elm shows "Could not publish post. Please try again." `publishing` transitions to `Failure`.
- **Load failure (edit mode)**: Elm shows "Could not load post. Please try again." `loading` transitions to `Failure`.
- **Visibility ceiling exceeded**: Backend returns error, which surfaces as a save failure.
- **Not authenticated**: Save/Publish buttons are inert (token check in Elm).

### Elm State Machine
- **Page module**: `Page.Blog.Editor`
- **Model fields involved**: `mode : Mode` (New | Edit String), `title : String`, `body : String`, `visibility : Visibility`, `saving : RemoteData`, `publishing : RemoteData`, `loading : RemoteData`
- **Msg flow**: `SetTitle/SetBody/SetVisibility -> SaveDraft -> SaveCompleted -> (if publishing) -> PublishCompleted`
- **RemoteData states**: saving: NotAsked -> Loading -> Success/Failure; publishing: NotAsked -> Loading -> Success/Failure

## 3. API Calls

### `POST /api/blog/posts` (create)
- **Auth**: Required (JWT Bearer token)
- **Pipeline**: `:api`, `:authenticated`
- **Controller**: `StacksWeb.BlogController.create/2`
- **Request body**: `{ title: string, body: string, visibility?: "owner" | "group" | "platform" }`
- **Response (success)**: `{ post: { id, user_id, title, body, visibility, published_at, created_at, updated_at } }` -- HTTP 201
- **Response (error)**: Changeset errors or `:visibility_ceiling` -- HTTP 422

### `PUT /api/blog/posts/:id` (update)
- **Auth**: Required (JWT Bearer token)
- **Pipeline**: `:api`, `:authenticated`
- **Controller**: `StacksWeb.BlogController.update/2`
- **Request body**: `{ title?, body?, visibility? }`
- **Response (success)**: `{ post: {...} }` -- HTTP 200
- **Response (error)**: `:not_found` (404), `:unauthorized` (403), `:visibility_ceiling` (422)

### `DELETE /api/blog/posts/:id` (delete)
- **Auth**: Required (JWT Bearer token)
- **Pipeline**: `:api`, `:authenticated`
- **Controller**: `StacksWeb.BlogController.delete/2`
- **Response (success)**: `{ deleted: true }` -- HTTP 200
- **Response (error)**: `:not_found` (404), `:unauthorized` (403)

### `POST /api/blog/posts/:id/publish` (publish)
- **Auth**: Required (JWT Bearer token)
- **Pipeline**: `:api`, `:authenticated`
- **Controller**: `StacksWeb.BlogController.publish/2`
- **Response (success)**: `{ post: {...} }` -- HTTP 200 (with `published_at` set)
- **Response (error)**: `:not_found` (404), `:unauthorized` (403)

## 4. Auth & Middleware Guards

- **Plugs fired** (in order): `SecurityHeaders` -> `AuthPipeline` (`:authenticated` scope) -> controller action
- **Visibility checks**: All write operations use `check_ownership/2` pattern matching `post.user_id == user.id`. All read operations filter by viewer via `Visibility.can_view?/2`.
- **Age gate**: N/A
- **Ownership checks**: `Blog.check_ownership/2` and controller `check_ownership/2` -- both verify `post.user_id == user.id`.

## 6. Event Flow & Lifecycle

### Events Emitted
- **Event type**: `blog.post_created`
- **Aggregate**: type `"post"`, ID is the post UUID
- **Payload**: `%{user_id, title, visibility}`
- **Emitted by**: `Stacks.Blog.create_post/2`
- **Emission method**: `Events.emit_safe/1`

- **Event type**: `blog.post_updated`
- **Aggregate**: type `"post"`, ID is the post UUID
- **Payload**: `%{user_id, title, visibility}`
- **Emitted by**: `Stacks.Blog.update_post/3`

- **Event type**: `blog.post_published`
- **Aggregate**: type `"post"`, ID is the post UUID
- **Payload**: `%{user_id, title}`
- **Emitted by**: `Stacks.Blog.publish_post/2`

- **Event type**: `blog.post_deleted`
- **Aggregate**: type `"post"`, ID is the post UUID
- **Payload**: `%{user_id}`
- **Emitted by**: `Stacks.Blog.delete_post/2`

### Event Handlers Triggered
- `blog.post_published` -> `Stacks.Blog.Handlers.BlogAssociationHandler` (enqueues LLM association job) + `Stacks.Workers.DbtRefreshHandler`
- `blog.post_updated` -> `Stacks.Workers.DbtRefreshHandler` + `Stacks.Blog.Handlers.WritingAssistantNudgeHandler` (debounced — enqueues `WritingAssistantNudgeWorker` at most once per 10 minutes per post)
- `blog.post_deleted` -> `Stacks.Workers.DbtRefreshHandler`

## 7. Background Jobs (Oban)

### `Stacks.Workers.PostBookAssociationWorker` (triggered by publish)
- **Worker**: `Stacks.Workers.PostBookAssociationWorker`
- **Queue**: `:default`
- **Args**: `%{ "post_id" => post_id }`
- **Max attempts**: 3
- **Trigger chain**: `blog.post_published` event -> `BlogAssociationHandler.handle_event/1` -> enqueues `PostBookAssociationWorker`
- **What it does**: See US-12.1.2 for full details.

### `Stacks.Workers.WritingAssistantNudgeWorker` (triggered by save)
- **Worker**: `Stacks.Workers.WritingAssistantNudgeWorker`
- **Queue**: `:default`
- **Args**: `%{ "post_id" => post_id, "user_id" => user_id }`
- **Max attempts**: 2
- **Trigger chain**: `blog.post_updated` event -> `WritingAssistantNudgeHandler.handle_event/1` (debounced, max once per 10 min per post) -> enqueues `WritingAssistantNudgeWorker`
- **What it does**: Calls `Stacks.AI.WritingAssistantClient` to generate a single proactive observation against the current post body and user's RAG context. Stores result in `op.blog_assistant_sessions`. The Elm editor polls or receives the nudge via SSE. See US-12.2.1 for full details.

## 12. Elm Frontend State Machine (Detail)

### Route
- **Route variant**: `Route.BlogNew` (new), `Route.BlogEdit postId` (edit)
- **URL**: `/blog/new`, `/blog/posts/:id/edit`
- **Public or authenticated**: Authenticated

### Init
- **New mode**: `mode = New, title = "", body = "", visibility = Owner, saving = NotAsked, publishing = NotAsked, loading = NotAsked`
- **Edit mode**: Same but `mode = Edit postId`, `loading = Loading`, fires `Api.getBlogPost postId maybeToken PostLoaded`

### Update cycle
- **Msg**: `SetTitle String` -- updates title, resets saving state.
- **Msg**: `SetBody String` -- updates body, resets saving state.
- **Msg**: `SetVisibility String` -- parses to Visibility type (Owner/Group/Platform), resets saving state.
- **Msg**: `SaveDraft` -- requires token. Sends `Api.createBlogPost` (New) or `Api.updateBlogPost` (Edit). Sets `saving = Loading`.
- **Msg**: `Publish` -- requires token. Sets `publishing = Loading, saving = Loading`. Sends save first; on success fires publish.
- **Msg**: `SaveCompleted (Ok newId)` -- sets `saving = Success ()`, switches mode to `Edit newId` if was New. If publishing was Loading, fires `Api.publishBlogPost`.
- **Msg**: `SaveCompleted (Err err)` -- sets `saving = Failure err`, resets publishing.
- **Msg**: `PublishCompleted (Ok _)` -- sets `publishing = Success ()`.
- **Msg**: `PublishCompleted (Err err)` -- sets `publishing = Failure err`.
- **Msg**: `PostLoaded (Ok post)` -- populates title, body, visibility from loaded post. Sets `loading = Success ()`.
- **Msg**: `PostLoaded (Err err)` -- sets `loading = Failure err`.

### View
- **Key elements**:
  - Title: "New Post" or "Edit Post"
  - Loading/error states for edit mode
  - Form: Title input, Body textarea (20 rows), Visibility select
  - Actions: Save Draft button (`btn--secondary`), Publish button (`btn--primary`)
  - Feedback: Error messages for save/publish failures
- **ARIA attributes**: N/A
- **CSS classes**: `page--blog-editor`, `blog-editor__form`, `form-field`, `form-field__input`, `form-field__textarea`, `form-field__select`, `blog-editor__actions`, `btn--secondary`, `btn--primary`, `btn--disabled`

## 13. Operational Metrics

- **Blog CRUD operation counts**: `blog.post_created`, `blog.post_updated`, `blog.post_published`, `blog.post_deleted` events provide full lifecycle tracking. Segmented by visibility level for distribution analysis.
- **Draft vs. publish ratio**: Ratio of created posts (drafts) to published posts. A high ratio of unpublished drafts may indicate UX friction in the publish flow.
- **Publish-triggered job enqueue rate**: Count of `PostBookAssociationWorker` jobs enqueued via `BlogAssociationHandler` after `blog.post_published` events. Should be 1:1 with publish events.
- **Audit log write throughput**: Blog operations do not write to the audit log directly, but events are captured in `event_log` via `Events.emit_safe/1`.

---

## 14. Performance & Usability Metrics

- **Blog post create latency**: Round-trip time for `POST /api/blog/posts`. Single-row INSERT on `op.blog_posts` plus event emission.
- **Blog post update latency**: Round-trip time for `PUT /api/blog/posts/:id`. Single-row UPDATE plus event emission.
- **Blog publish latency**: Round-trip time for `POST /api/blog/posts/:id/publish`. UPDATE to set `published_at` plus event emission plus async job enqueue.
- **Blog publish to LLM association time**: End-to-end time from `blog.post_published` event to `blog.associations_suggested` event. Includes event dispatch, job enqueue, LLM API call, and association persistence. See US-12.1.2 for detailed breakdown.
- **Editor load time (edit mode)**: Time from navigation to `PostLoaded (Ok post)` for the `Api.getBlogPost` call when editing an existing post.

---

## 15. Cost Tracking

- **Neon**: Minimal compute cost for CRUD operations -- single-row INSERT/UPDATE/DELETE on `op.blog_posts`. The publish operation is slightly more expensive due to event emission and job enqueue.
- **Together AI** (indirect, publish): Publishing triggers `PostBookAssociationWorker` — per-token cost for LLM analysis of post body + book catalogue. See US-12.1.2 for detailed cost breakdown.
- **Together AI** (indirect, save): Each save may trigger `WritingAssistantNudgeWorker` (debounced, max once per 10 min) — per-token cost for `Llama-3.3-70B-Instruct-Turbo` proactive nudge generation against RAG context. See US-12.2.1 for detailed cost breakdown.
- **Modal**: `WritingAssistantNudgeWorker` calls the `apps/writing_assistant` Modal service — compute cost per invocation.
- **dbt**: `blog.post_published`, `blog.post_updated`, `blog.post_deleted` all trigger `DbtRefreshHandler`, incurring Neon compute cost for dbt model refreshes.
- No direct storage or email costs for the write/publish flow.
