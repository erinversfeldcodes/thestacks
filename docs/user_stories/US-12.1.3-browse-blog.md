# US-12.1.3 — Browse Another User's Blog

## 1. User Story

> **As a** platform user, **I want to** read another user's blog posts **so that** I can follow their reading life and thinking.

From a public profile, the user navigates to the "Writing" tab. They see a list of posts scoped to their visibility level (only posts the author has made visible to this viewer). They click a post to read it in full.

**What they see on the page:**
- The writing tab shows post cards: title, date, opening lines, and a read-time estimate.
- The post page is clean and typographic -- the author's name and date at the top, the body in a readable serif, and the book associations section at the bottom.
- No algorithmic recommendations or infinite scroll. The archive is a simple reverse-chronological list.

---

## 2. UI Interaction Flow

### Happy Path (Browse Archive)
1. User navigates to another user's blog archive page.
2. System sends `GET /api/blog/posts?user_id=<author_id>`.
3. Controller builds the viewer context from the authenticated user (or `:unauthenticated`).
4. `Blog.list_user_posts/2` returns only published posts visible to the viewer.
5. Archive page renders a list of post cards.

### Happy Path (Read Post)
1. User clicks a post card.
2. System sends `GET /api/blog/posts/:id`.
3. Controller calls `Blog.get_post_for_viewer/2` which checks `Visibility.can_view?/2`.
4. If visible, returns the post with its associations (non-owner sees only visible associations).
5. Post page renders with body and book associations section.

### Sad Paths
- **Post not found or not visible**: `Blog.get_post_for_viewer/2` returns `nil`. Controller returns `{:error, :not_found}`. FallbackController returns HTTP 404.
- **Author not found or profile hidden**: `list_user_posts/2` returns empty list due to visibility filtering.
- **Blocked user**: `Visibility.resolve_visibility/2` checks `Social.blocked?/2` bidirectionally. Blocked content returns `:hidden`.
- **Load failure**: Elm shows "Could not load posts. Please try again." or "Could not load post. Please try again."

### Elm State Machine
- **Page module**: `Page.Blog.Archive` (list) + `Page.Blog.Post` (detail)
- **Model fields involved**: Archive: `posts : RemoteData Http.Error (List BlogPostSummary)`, `isAuthenticated : Bool`. Post: `post : RemoteData Http.Error BlogPost`.
- **Msg flow**: Archive: `PostsLoaded (Ok/Err)`. Post: `PostLoaded (Ok/Err)`.
- **RemoteData states**: Loading -> Success / Failure

## 3. API Calls

### `GET /api/blog/posts?user_id=<author_id>` (list posts)
- **Auth**: Optional (JWT Bearer token)
- **Pipeline**: `:api` (optional auth scope for public blog content)
- **Controller**: `StacksWeb.BlogController.index/2`
- **Query params**: `user_id` (required)
- **Response (success)**: `{ posts: [{ id, user_id, title, body, visibility, published_at, created_at, updated_at }] }` -- HTTP 200
- **Response (error)**: `{ error: "user_id is required" }` -- HTTP 422 (missing param)
- **Visibility filtering**:
  - If viewer is the owner (`{:platform_user, ^user_id}`): returns all posts including unpublished drafts, ordered by `created_at desc`.
  - If viewer is anyone else: returns only published posts (`published_at` is not nil), ordered by `published_at desc`, filtered by `Visibility.can_view?/2`.

### `GET /api/blog/posts/:id` (show post with associations)
- **Auth**: Optional (JWT Bearer token)
- **Pipeline**: `:api` (optional auth scope)
- **Controller**: `StacksWeb.BlogController.show/2`
- **Response (success)**: `{ post: {...}, associations: [{ id, book_id, confidence, source, visible, reasoning? }] }` -- HTTP 200
- **Response (error)**: `{:error, :not_found}` -- HTTP 404
- **Association filtering**:
  - Owner sees all associations (including hidden) with `reasoning` field.
  - Non-owner sees only associations where `visible == true`, without `reasoning`.

---

## 4. Auth & Middleware Guards

- **Plugs fired** (in order): `SecurityHeaders` -> optional `AuthPipeline` -> controller action
- **Visibility checks**:
  1. **Profile ceiling**: If the author's `profile_visibility == "owner"`, all posts are hidden from non-owners.
  2. **Block check**: `Social.blocked?/2` bidirectional. Neither blocked party sees the other's posts.
  3. **Post visibility**: `Visibility.can_view?/2` checks the post's `visibility` field against the viewer context.
- **Viewer construction**: `build_viewer/1` in BlogController extracts the viewer from `Guardian.Plug.current_resource(conn)`:
  - `nil` -> `:unauthenticated`
  - `%{id: id}` -> `{:platform_user, id}`
- **Age gate**: N/A for posts (age gate only applies to books).
- **Ownership checks**: Read-only access does not require ownership.

## 5. Database Interactions

### Read: List user posts with visibility filtering
- **Table(s)**: `op.blog_posts`
- **Query** (owner viewing own posts): `from p in Post, where: p.user_id == ^user_id, order_by: [desc: p.created_at]`
- **Query** (non-owner): `from p in Post, where: p.user_id == ^user_id and not is_nil(p.published_at), order_by: [desc: p.published_at]`
- **Post-filter**: `Enum.filter(&Visibility.can_view?(&1, viewer))`
- **Module**: `Stacks.Blog.list_user_posts/2`

### Read: Get single post for viewer
- **Table(s)**: `op.blog_posts`
- **Query**: `Repo.get(Post, id)` then `Visibility.can_view?(post, viewer)`
- **Returns**: `Post.t() | nil`
- **Module**: `Stacks.Blog.get_post_for_viewer/2`

### Read: List associations for post
- **Table(s)**: `op.post_book_associations`
- **Query**: `from a in PostBookAssociation, where: a.post_id == ^post_id, order_by: [desc: a.confidence]`
- **Module**: `Stacks.Blog.list_associations/1`

### Read: Posts for a book (cross-reference)
- **Table(s)**: `op.blog_posts`, `op.post_book_associations`
- **Query**: `from p in Post, join: a in PostBookAssociation, on: a.post_id == p.id, where: a.book_id == ^book_id and a.visible == true and not is_nil(p.published_at)`
- **Post-filter**: `Enum.filter(&Visibility.can_view?(&1, viewer))`
- **Module**: `Stacks.Blog.list_posts_for_book/2`

## 13. Operational Metrics

- **Blog post read counts**: Total `GET /api/blog/posts/:id` requests, segmented by whether the viewer is the owner or a non-owner. Tracks overall blog reading activity.
- **Blog archive list counts**: Total `GET /api/blog/posts?user_id=<id>` requests. Tracks how often users browse other users' writing archives.
- **Visibility filtering drop rate**: Percentage of posts filtered out by `Visibility.can_view?/2` during `list_user_posts/2`. A high drop rate means users are browsing profiles where most posts are private -- expected for "owner"-visibility profiles.
- **Block-hidden content rate**: Count of blog reads that return `:hidden` due to `Social.blocked?/2` bidirectional check. Tracks how often the block system affects blog browsing.

---

## 14. Performance & Usability Metrics

- **Blog archive load time**: Round-trip time for `GET /api/blog/posts?user_id=<id>`. Includes the DB query plus in-memory `Visibility.can_view?/2` filtering on each post. Scales with the author's total post count.
- **Blog post read counts per visibility level**: Distribution of successful post reads segmented by the post's `visibility` field (owner, group, platform). Indicates which visibility tiers generate the most reader traffic.
- **Single post load time**: Round-trip time for `GET /api/blog/posts/:id` including association fetch (`list_associations/1`). The association query adds a second DB round-trip ordered by confidence.
- **Cross-reference query latency**: Time for `Blog.list_posts_for_book/2`, which JOINs `blog_posts` with `post_book_associations` and applies visibility filtering. Used on book detail overlays to show related writing.

---

## 15. Cost Tracking

- All blog browsing operations are read-only DB queries with no external service calls.
- **Neon**: Compute cost for queries on `op.blog_posts` (list and single-post fetch) plus `op.post_book_associations` (association listing). The cross-reference query (`list_posts_for_book/2`) involves a JOIN and is the most expensive read path.
- Visibility resolution via `resolve_visibility/2` adds overhead per post: profile ceiling check, block check (bidirectional query on `op.user_blocks`), and resource visibility check. This is the same cost as any visibility-protected content access.
- No storage, email, or LLM costs. Blog browsing is purely a read-path operation with costs driven by Neon query compute.
