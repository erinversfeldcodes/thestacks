# US-10.5.2 — View a Reader's Public Profile

> The reader-facing consumer of the visibility model. This is the surface where
> profile visibility (US-10.1.1), blocking (US-10.1.2), and bookshelf visibility
> (US-10.2.1) actually *do something a viewer can observe*. Before this, those
> controls were enforced but had no consuming UI.

## 1. User Story

**As a** reader, **I want to** view another reader's profile at `/u/:handle`
**so that** I can see who they are and which of their bookshelves they've made
visible to me.

### Acceptance criteria — the profile visibility matrix

`GET /api/u/:handle` resolves the viewer (`{:platform_user, id}` when signed in,
`:unauthenticated` otherwise) and gates the hub:

| Viewer → / Target profile ↓ | **platform** ("Discoverable") | **owner** ("Ghost") |
|---|---|---|
| **Owner viewing own handle** | 200 — own profile | 200 — own profile |
| **Authenticated non-owner, not blocked** | 200 — redacted profile + viewer-visible shelves | **404 not found** |
| **Authenticated, blocked either direction** | **404** | **404** |
| **Unauthenticated** | 200 — redacted profile + platform-visible shelves | **404** |

- A hidden profile is **404, never 403** — a ghost or a blocked user is
  indistinguishable from a non-existent one (mirrors the block-404 rule).
- The shelf list contains **only bookshelves the viewer may see**, computed by
  `Stacks.Visibility.viewable_shelves(target_id, viewer)`: a `platform` shelf
  shows to any allowed viewer, an `owner` shelf never shows to others, a `group`
  shelf shows only to members of its group.
- The payload is **redacted**: `handle, display_name, website_url, city,
  country_code, bookshelves[].name` ONLY — never email, consent flags, role, or
  notification prefs.
- An unknown handle → 404.

## 2. UI Interaction Flow

### Happy path
Navigate to `/u/:handle` → hub renders the reader's display name, `@handle`,
location + website, and a list of their visible bookshelves as links (each → the
browse view, US-10.5.3).

### Sad paths
- Ghost / blocked / unknown handle → neutral "Reader not found" card (same for all three — no information leak).

### Elm state machine
`Page.Profile` init fires `Api.getProfile maybeToken handle`; `GotProfile (Ok p)` → `Success p`; `GotProfile (Err _)` → `Failure` (renders "not found"); a 401 → `SessionExpired` OutMsg.

## 3. API Calls

### `GET /api/u/:handle` → `ProfileController.show`
`:optional_auth` pipeline. Resolves handle → target (404 if none); ghost/block gate via `Visibility.profile_visible?/2` → 404; else `ProtoJSON.public_profile(target, viewable_shelves(target.id, viewer))`.

## 4. Auth & Middleware Guards
`:optional_auth` (`Guardian.Plug.LoadResource, allow_blank: true`) — works signed in or out. No auth is *required*; the viewer identity only changes *what* is returned. Ghost/block gate is the security boundary.

## 5. Database Interactions
- `Accounts.get_user_by_handle/1` (case-insensitive).
- `Visibility.viewable_shelves(target_id, viewer)` — loads the target's bookshelves, filters by `can_view?/2` (profile ceiling + block + resource visibility + group membership, all baked into `resolve_visibility/2`).

## 12. Elm Frontend State Machine (Detail)
- **Route**: `Route.Profile String` = `/u/:handle`.
- **Init**: `Page.Profile.init maybeToken handle` → `Loading` + `Api.getProfile`.
- **Update**: `GotProfile Ok/Err`; `Err isUnauthorized` → `SessionExpired`.
- **View**: hub header (name/@handle/location/website) + `viewShelves` (links to `Route.ProfileShelf handle name`), or "Reader not found".
