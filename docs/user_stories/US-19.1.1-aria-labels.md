# US-19.1.1 — ARIA Labels for Visual Elements

## 1. User Story

> **As a** user who relies on a screen reader, **I want** the visual bookshelf, spine, and detail overlay elements to have meaningful ARIA labels **so that** I can navigate and understand my collection without relying on visual cues.

**Acceptance criteria:**
- All book spines have descriptive `aria-label` attributes
- Bookshelf containers use `role="list"` with shelf name and book count (spec; not yet fully implemented)
- The book detail overlay uses `role="dialog"` with focus trapping
- Upload flow progress is announced via `aria-live` regions
- All interactive elements are keyboard-focusable and operable

## 2. UI Interaction Flow

### What Exists in the Codebase

**Book Spines** (`Components.Spine`):
- Each spine has `attribute "aria-label" ariaLabel` where `ariaLabel` is constructed as:
  `"Book: [title] by [author], [pageCount] pages[wearSuffix]"`
- Wear suffix: `""` for `Pristine`, `", well-loved"` for `Softened`.
- The spine also has a `title` attribute: `"[title] — [author]"`.

**Login Form** (`Page.Login`):
- Tab container: `attribute "role" "tablist"`
- Each tab button: `attribute "role" "tab"`, `attribute "aria-selected" "true"/"false"`
- Email and password inputs: `attribute "aria-required" "true"`
- Error display: `div [ attribute "aria-live" "polite" ]` — errors are announced to screen readers.

**User Menu** (`Components.UserMenu`):
- Container: `attribute "aria-label" "User menu"`
- Trigger button: `attribute "aria-expanded" (boolToString model.open)`, `attribute "aria-haspopup" "true"`

**Onboarding Overlay** (`Components.OnboardingOverlay`):
- Overlay container: `attribute "role" "dialog"`, `attribute "aria-modal" "true"`, `attribute "aria-label" "Welcome to The Stacks"`, `tabindex -1`

**Book Detail Overlay** (in Main.elm):
- Focus management: When overlay opens, `Browser.Dom.focus "book-overlay-close"` is called to move focus to the close button.
- When overlay closes, focus returns to the triggering spine element via `Browser.Dom.focus ("spine-" ++ bookId)`.

**Navigation** (in Main.elm):
- `<nav>` element: `attribute "aria-label" "Main navigation"`

**Bookshelf Container** (`Page.Bookshelf`):
- `div [ attribute "aria-live" "polite" ]` wraps the bookshelf content to announce updates.

**Book List** (`Components.BookList`):
- Table: `attribute "role" "table"`
- Column headers: `scope "col"`, `attribute "aria-sort" "ascending"/"descending"/"none"`
- Rows: `attribute "role" "row"`

**View Mode Toggle** (`Components.ViewModeToggle`):
- Container: `attribute "role" "group"`, `attribute "aria-label" "View mode"`
- Each button: `attribute "aria-pressed" "true"/"false"`, `attribute "aria-label" "Spine view"/"List view"`

**Skip Link** (in Main.elm):
- `a [ class "skip-link", href "#main-content" ] [ text "Skip to main content" ]`
- Main content area: `main_ [ id "main-content" ]`

### What Is Missing (per spec)
- Bookshelf containers do not yet use `role="list"` with `aria-label` showing shelf name and book count (e.g., "Library — 12 books"). _(Partially addressed in #318 8f: the shelf-row `role="list"` container now carries an `aria-label` — "Shelf — N book(s)", correctly pluralised — though it names the row, not the bookshelf's own name/full count.)_
- Shelf rows within the bookcase do not have `role="listitem"` groupings. _(Note: individual spines DO carry `role="listitem"` via `viewSpine`; the outstanding gap is a named grouping.)_
- Wear state detail (well-read, cracking, etc.) is only partially covered — only `Pristine` and `Softened` are in the spine ARIA label.
- ~~Upload flow `aria-live` regions for progress ("Processing image...", "Book identified...") are not implemented.~~ **DONE** — `Page.Upload.view` wraps the whole status surface in `div [ aria-live "polite", class "upload-status-region" ]`, so every progress/result/failure state is announced. Regression-tested (`UploadProgramTest.uploadProgressIsAnAriaLiveRegion`).

**Grid arrow-key navigation** (acceptance criterion "All interactive elements are keyboard-focusable and operable"): the grid is fully keyboard-operable via Tab today; full arrow-key roving-tabindex is an explicit DEFER — see the Decision block in **US-19.1.2**.

### CSS Support

**Focus indicators** (`frontend/css/main.css`):
- `*:focus-visible` — `outline: 2px solid #d4a029; outline-offset: 2px;`
- `.book-button:focus-visible` — amber outline
- `.book-overlay__close:focus-visible` — amber outline
- `.btn:focus-visible` — amber outline
- `.app-nav__link:focus-visible` — amber outline
- `.book-pile__book:focus-visible .book` — `outline: 2px solid var(--accent); outline-offset: 2px;`

**Skip link** (`frontend/css/main.css`):
- `.skip-link` — positioned `top: -100%` (hidden off-screen)
- `.skip-link:focus` — `top: 0; outline: 2px solid var(--text)` (becomes visible on focus)

## 13. Operational Metrics

- **ARIA attribute coverage**: Percentage of interactive elements that have appropriate ARIA attributes. Tracked via automated accessibility audits (e.g., axe-core, Lighthouse).
- **Missing ARIA label count**: Number of interactive elements flagged as missing `aria-label`, `aria-labelledby`, or visible text. Target: zero.
- **Role assignment completeness**: Percentage of custom widgets with correct `role` attributes (dialog, tablist, tab, group, table, row).
- **`aria-live` region count**: Number of live regions in the application. Currently: login error display, bookshelf content wrapper.
- **Focus management success rate**: Percentage of overlay open/close cycles where focus is correctly moved (to close button on open, back to trigger on close).

---

## 14. Performance & Usability Metrics

- **Accessibility audit score**: Lighthouse accessibility score and axe-core violation count. Target: 95+ Lighthouse score, zero critical violations.
- **Screen reader compatibility**: Manual testing coverage across VoiceOver (macOS/iOS), NVDA (Windows), and JAWS. Track pass/fail per component.
- **ARIA label accuracy**: Whether `aria-label` values accurately describe the element (e.g., spine labels include title, author, page count, wear state).
- **Missing spec coverage**: Gap between spec requirements and implementation — bookshelf `role="list"` with count, shelf row `role="listitem"`, upload `aria-live` progress regions.
- **Wear state coverage**: Currently only `Pristine` and `Softened` are in spine ARIA labels. Track implementation of remaining wear states.
- **Focus indicator visibility**: Whether `*:focus-visible` outlines are visible against all background colors used in the platform.
