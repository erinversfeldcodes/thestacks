# US-6.1 — Subscribe to Shelf RSS Feeds

## 1. User Story

> **As a** user (or a friend of the user), **I want** each public shelf to have an Atom feed **so that** I can follow what someone is reading and discover books through their collection.

Each public shelf (Library, AntiLibrary, WishList, Reading Pile) automatically generates an Atom feed. The feed URL is accessible from the shelf page -- a small RSS icon in the shelf header. Friends subscribe using any RSS reader. Feed entries look like: "Erin moved The Secret History to Library" or "Erin added Piranesi to the Reading Pile" -- each with the book title, author, cover thumbnail, and timestamp.

---

## 2. UI Interaction Flow

### Happy Path
1. User views a bookshelf page.
2. If the bookshelf has `visibility: "platform"`, an RSS icon button renders in the shelf header (via `Components.RSSLink`).
3. User clicks the RSS icon button.
4. A popover displays with the feed URL and the text "Subscribe in your RSS reader:".
5. User copies the URL and adds it to their RSS reader.
6. RSS reader fetches `GET /api/feeds/:user_id/:bookshelf_name` -- receives Atom 1.0 XML.

### Sad Paths
- **Non-public bookshelf**: `Components.RSSLink` renders nothing when `visibility /= "platform"`.
- **Bookshelf not found**: `FeedController` returns 404 — `{ error: "Bookshelf not found" }`.
- **Bookshelf not platform-visible**: `FeedController` returns 403 — `{ error: "Feed is only available for platform-visible bookshelves" }`.
- **No placements**: Feed generates with empty entries (valid Atom XML with no `<entry>` elements).
- **304 Not Modified**: If client sends `If-None-Match` matching the current ETag, returns 304 with empty body.

### Elm State Machine
- **Component module**: `Components.RSSLink`
- **Model fields involved**: `showUrl : Bool`
- **Msg flow**: `ToggleUrl` -> toggles `showUrl`
- **OutMsg pattern**: N/A

---

## 3. API Calls

### `GET /api/feeds/:user_id/:bookshelf_name`
- **Auth**: None (public endpoint)
- **Pipeline**: `:api` -> `:rate_limit_public`
- **Controller**: `StacksWeb.FeedController.show/2`
- **Request headers**: Optional `If-None-Match` for ETag caching
- **Response (success)**: Atom 1.0 XML — HTTP 200
  - `Content-Type: application/atom+xml`
  - `ETag: "md5hex"`
  - `Cache-Control: public, max-age=300`
- **Response (304)**: Empty body when `If-None-Match` matches ETag
- **Response (error)**:
  - `{ error: "Bookshelf not found" }` — HTTP 404
  - `{ error: "Feed is only available for platform-visible bookshelves" }` — HTTP 403

## 4. Auth & Middleware Guards

- **Plugs fired**: `SecurityHeaders` -> `RateLimiter(bucket: :public)`
- **Visibility checks**: `Feeds.generate_atom/2` checks `bookshelf.visibility == "platform"` — returns `{:error, :not_public}` otherwise
- **Age gate**: N/A — feed contains metadata only, not full book content
- **Ownership checks**: N/A — public endpoint, no ownership required

## 5. Database Interactions

### Read: Bookshelf record
- **Table(s)**: `op.bookshelves`
- **Query**: `Shelving.get_bookshelf(user_id, bookshelf_name)` — finds the bookshelf and checks visibility
- **Schema module**: `Stacks.Shelving.Bookshelf`

### Read: Bookshelf placements with books
- **Table(s)**: `op.bookshelf_placements` JOIN `op.books` JOIN `op.authors` JOIN `op.book_editions`
- **Query**: `Shelving.get_bookshelf_books(user_id, bookshelf_name)` — returns placements with preloaded book, author, and editions
- **Schema module**: `Stacks.Shelving.Placement`

## 6. Event Flow & Lifecycle

### Events Emitted
N/A — feed generation does not emit events.

### Event Handlers Triggered (upstream)
- **Handler**: `Stacks.Feeds.Handlers.PlacementHandler`
- **Listens for**: `placement.created`, `placement.moved`, `placement.removed`
- **Action**: Enqueues `RegenerateFeedJob` for the affected bookshelf(s)
  - For `placement.moved`: regenerates feeds for both source and destination bookshelves
  - For `placement.removed`: enqueues regeneration (bookshelf name extracted from payload)
- **Downstream effects**: Feed XML regenerated and cached (if caching is implemented)

---

## 7. Background Jobs (Oban)

### RegenerateFeedJob
- **Worker**: `Stacks.Workers.RegenerateFeedJob`
- **Queue**: `:default` (presumed)
- **Args**: `%{"user_id" => uuid, "bookshelf_name" => name}`
- **Max attempts**: Default
- **What it does**: Regenerates the Atom XML for the specified bookshelf. If feed caching is implemented, updates the cached version.
- **On success**: Feed ready for next request
- **On failure**: Feed regenerated on-demand by `FeedController`

## 10. Cache Interactions

- **Cache**: HTTP-level ETag caching
- **Operation**: ETag computed as MD5 of generated XML (`Feeds.compute_etag/1`), returned in response header
- **Key**: ETag string (hex-encoded MD5)
- **TTL**: `Cache-Control: public, max-age=300` (5 minutes)
- **Invalidation trigger**: Feed content changes when placements change — `RegenerateFeedJob` enqueued by `PlacementHandler`

### Atom Feed XML Structure
```xml
<?xml version="1.0" encoding="utf-8"?>
<feed xmlns="http://www.w3.org/2005/Atom">
  <title>{displayName}'s {Bookshelf Name}</title>
  <id>urn:stacks:feed:{bookshelf_id}</id>
  <updated>{latest_placement_date}</updated>
  <author><name>{displayName}</name></author>
  <entry>
    <title>{book_title}</title>
    <id>urn:stacks:placement:{placement_id}</id>
    <updated>{placed_at}</updated>
    <summary>{title} by {author} added to {bookshelf}</summary>
    <author><name>{author_name}</name></author>
    <link rel="related" href="https://openlibrary.org/isbn/{isbn}" />
  </entry>
</feed>
```

## 13. Operational Metrics

- **Oban job counts for `RegenerateFeedJob`**: enqueued (per `placement.created`, `placement.moved`, `placement.removed` events), completed, failed, retried
- **Feed generation counts**: number of `GET /api/feeds/:user_id/:bookshelf_name` requests -- 200 (full response), 304 (ETag cache hit), 403 (not public), 404 (not found)
- **ETag cache hit rate**: ratio of 304 responses to total feed requests -- higher is better, indicates RSS readers caching effectively
- **Event handler execution times**: `PlacementHandler` latency from placement events to `RegenerateFeedJob` enqueue -- for `placement.moved`, two jobs are enqueued (source + destination bookshelves)
- **Rate limiter activity**: `:rate_limit_public` bucket for feed endpoint -- monitors for aggressive RSS reader polling

---

## 14. Performance & Usability Metrics

- **RSS feed generation time**: elapsed time to generate Atom XML for a bookshelf -- depends on placement count. Target: <100ms for bookshelves with <500 placements.
- **Feed XML size**: bytes per generated feed -- affects RSS reader fetch times and network egress
- **Feed subscriber count**: unique `User-Agent` strings or IP addresses hitting feed URLs -- proxy for how many RSS readers are subscribed
- **Feed freshness**: time between a placement event and the feed reflecting the change -- `RegenerateFeedJob` latency + `max-age=300` cache header means up to ~5 minutes delay
- **Feed entry quality**: percentage of entries with complete metadata (book title, author name, ISBN link) vs entries with missing fields

## 15. Cost Tracking

- **Fly.io compute**: core app machine time for `RegenerateFeedJob` (event-triggered) and `FeedController.show/2` (on-demand). Feed generation is CPU-light (string concatenation + MD5 hash). Fly.io shared-cpu-1x: ~$1.94/month base.
- **Neon compute**: feed generation queries `op.bookshelves`, `op.bookshelf_placements`, `op.books`, `op.authors`, `op.book_editions` with preloads. One multi-join query per feed request (or per regeneration job). Neon free tier: 191.9 compute hours/month; paid: $0.16/compute-hour.
- **Network egress**: Atom XML served to RSS readers. Typical feed size: 5-50KB. With `Cache-Control: public, max-age=300`, well-behaved readers poll at most every 5 minutes. 100 subscribers polling every 5 minutes: ~1.4GB/month. Fly.io free tier: 100GB/month; $0.02/GB after.
- **No external API costs**: feed generation is entirely local -- no Brave, Together AI, or scraper calls.
