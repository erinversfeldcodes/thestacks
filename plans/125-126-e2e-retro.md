**Date**: 2026-07-26 · **Branch**: `feat/125-126-e2e` · 14 commits, 32 files, +3,407/−406

## What worked well
- **Re-verifying the 2.5-week-old baseline audits before planning** paid for itself immediately: 3 of 9 (#125) and 5 of 25 (#126) punch items were already closed by intervening work, and several audit claims were inverted (the "no global 401 handler" premise, PII-free event payloads, the removed age-verification surface). Tests written to the stale baselines would have asserted dead markup and wrong payloads.
- **The orchestrator live-drive as a hard gate caught two real bugs no other layer saw**: (a) CG-1 was broader than scoped — ALL UI profile saves 422'd, masked for exactly as long as the email-branch bug it sat behind; (b) the handle NOT-NULL 500, unmasked only after the CG-1 fix, invisible to unit tests because nothing ever sent `handle: ""`.
- **Far-end verification closed the #248-class gap**: querying the preview's Neon `event_log` directly proved the payload strip lives in a deployed environment, not just in test assertions.
- **Parallel specialist execution with disjoint path contracts** (frontend vs apps/core vs e2e vs dbt) ran up to four agents concurrently with zero merge conflicts; pathspec-limited commits kept each phase's diff clean.
- Reviewer quality was high: the elm-reviewer independently re-ran perturbations; the PE traced the same-email relaxation to prove no password bypass; the dbt reviewer reasoned about statement-snapshot semantics.
- **Zero reviewer-driven revision cycles** across 9 reviews — test-first + perturbation evidence + fresh orchestrator gate runs before review meant reviewers verified rather than discovered.

## What caused friction
- **Idle-notification ≠ completion-report churn**: multiple agents idled without reports and needed explicit demands (one needed three). The protocol's "ask for the report" rule worked but cost round-trips.
- **Port 4000 contention**: the dev HTTP port is hardcoded (`dev.exs`), so the 2b live-drive queued behind the #125 E2E agent's stack, and `just ci`'s DB steps forced a Phoenix shutdown. Sequencing worked but was hand-managed.
- **`STACKS_E2E_TEST_HELPERS` exact-value trap**: the gate requires exactly `"1"`; my first boot used `true` → all minted tests silently skipped. A skip-is-not-a-pass check caught it, but the flag's strictness is easy to trip.
- **The `:auth`-bucket 4-worker flake** surfaced mid-epic and required a diagnose-don't-dismiss detour; the preview run settled it (does not manifest on the gate env), but local full-suite runs must be serial until the follow-up lands.
- **CI failed twice at the end** (semgrep dynamic-RegExp, then dockle/no-Docker) — the semgrep rule wasn't on any earlier checklist, so a lint-class issue reached the epic gate.
- Two shared-file races needed hand-sequencing (issue Progress Notes across concurrent phases; the mid-flight elm-format Stop-hook failure from another agent's edit).

## What should change in the agent system
1. **`docs/agents/orchestrator-agent.md`** — add to Phase 1: "if the issue's embedded audit is older than ~1 week, a re-verification research pass is mandatory before planning" (this epic's biggest win; make it a rule, not a judgment call).
2. **`docs/agents/testing-coordinator-agent.md` / e2e docs** — document the `STACKS_E2E_TEST_HELPERS=1` exact-value requirement and the "skip is not a pass: probe the helper with a 201 before trusting a run" pattern.
3. **`docs/agents/standards/testing.md`** — add the semgrep `detect-non-literal-regexp` rule to the E2E-authoring conventions (use `:text-is()` / glob URL strings, never `new RegExp(dynamic)`), so it's caught at authoring, not at the epic CI gate.
4. **`justfile`/dev config** — consider honouring `PORT` in `dev.exs` so parallel agents can run stacks side-by-side; would have removed the biggest serialization constraint this epic.
5. **Follow-up issue (local ergonomics)**: bucket-aware serialization or a per-file worker cap for login-heavy spec files, so local full-suite runs don't need `--workers=1`.
6. **Subagent completion protocol** — require agents to send the completion report *in the same turn* as finishing (the repeated idle-without-report pattern suggests the prompt template's "SendMessage then stop" needs to be the FIRST closing action, not the last).
