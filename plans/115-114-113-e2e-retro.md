## What Worked Well

- **Live drives caught what 983 green unit tests could not.** The epic's headline validation: #115's Phase 3 live E2E found the search response-shape bug (bare-array decoder vs `{query,count,results}` object) that the entire unit layer missed because the test mirror simulated the same fiction. The path-mismatch bug was caught the same way. Two total live-wire breaks fixed; the "code-reading is not proof" and "mirror ≠ wire" lessons are now structurally enforced (single object-shaped response builder; mirror reuses the exposed decoder after #292).
- **Baseline re-verification before planning paid for itself immediately.** The 2026-07-08 audits were two weeks stale; the pre-kickoff research found six #114 punch items already closed by intervening merges and prevented double-work.
- **Adversarial verification layers were consistently non-vacuous.** Every child produced failing-first evidence; proving gates physically reverted features (path fix, spineWidth divisor, focus trap disable) and captured the resulting failures verbatim. The TC verification passes (13-1-0, all-PASS ×2) and the epic completion-audit's spot-verification found zero fabricated evidence tokens across 16 issues.
- **Scope-lock discipline held under pressure.** Three feature gaps discovered mid-#115 (inert sort/filter, click-through, sanitiser) were split correctly: bug-fix-in-scope vs spin-out. The eventual owner directive to complete all spin-outs on-branch validated keeping them small and well-specified.
- **The full-verify gate caught the class it exists for.** #284's `description_tsv` missing from dbt `sources.yml` — invisible to every scoped run — fell out of the first HEAD-wide `just verify`, exactly per the project memory.
- **Design decisions escalated at the right altitude.** The owner's "isn't advertising part of Phase 1?" challenge was resolved by evidence (US-18.1.1 `looking_for_home` + the US-10.2.2 marketplace exception), producing a #285 scope that is genuinely Phase-1-shaped rather than either extreme.

## What Caused Friction

- **Shared-tree, shared-index execution bit four times.** (1) A tree-wide `just ci` raced in-flight edits and produced a false failure; (2/3) two commit races swept other agents' staged/untracked files into the wrong commits (2479e0e8, f94cc35f); (4) an agent's `git checkout --` restore instruction — written by the orchestrator — destroyed another agent's uncommitted focus trap, requiring reconstruction from its test contract. Root cause: many agents, one working tree, one index, no commit serialization protocol.
- **Uncommitted work accumulated far too long.** The entire first three children sat uncommitted for hours because the orchestrator's commit attempts were permission-denied — the working form (`git -C <path> commit -m "<subject-only>"`, separate `git add`) was only discovered after the near-loss incident. The allowlisted command shape was tribal knowledge that should have been in memory from the start (now is).
- **The session limit killed four agents mid-flight** with partial, in some cases unparseable, tree state. The snapshot-patch + ledger recovery worked but cost a full reconstruction of the #287 Spine slice and a misattribution (the broken SearchProgramTest partial was #289's, initially logged as #287's).
- **Stale-server confusion recurred three times** (dev `code_reloader` off): new routes 404'd until restarts for #287, #284, and the #285 Phase-4 drive. Each agent rediscovered this independently.
- **One planning error became a revision cycle:** the #114 plan's paraphrase of event payloads ("moved carries book_id") contradicted the issue's own spec; the specialist correctly asserted reality, but the discrepancy consumed a triage round. Same class: the #291 brief framed the regex sanitiser as load-bearing; empirical testing disproved it (good outcome, wrong brief).
- **Upstream CVE landed mid-epic** (brace-expansion), failing two CI groups unrelated to the diff — plus a latent local-only inconsistency (Trivy scanning `.claude/worktrees` that Grype already excluded).
